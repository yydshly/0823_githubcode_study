# Hands-On LLM 跨章节能力地图

这份地图不是把12章再摘要一次，而是把13个实践压缩成一套可以迁移到其他AI仓库的研究方法。面对任何“它能生成、理解、检索、调用工具或微调”的描述，先沿着下面五步追问，再决定能力是否成立。

## 一条统一判断链

1. **数据：它实际吃进了什么？** 提示词、Token、标签、文档、图片、正负句对、chosen/rejected，还是工具返回值？训练、验证与测试是否独立？
2. **转换：模型或系统实际改变了什么？** Token ID、logits、Embedding、聚类、排序、工具观察，还是某一组可训练参数？
3. **目标：代码真正优化什么？** 下一Token交叉熵、分类交叉熵、余弦相似度、对比损失、聚类密度、LoRA增量或DPO相对margin？
4. **决策与指标：怎样从模型输出变成答案，怎样证明有效？** argmax、采样、阈值、Top-k、reranker、解析器和执行器分别承担什么责任？指标是否对应真实任务？
5. **失败边界：什么结论不能从当前证据推出？** loss下降不等于业务质量提高，相似度不等于真假概率，生成文本不等于回答有用，工具计算正确不等于最终回答正确。

这五步把“模型有什么能力”改写成一组可检查对象：**数据契约 → 转换机制 → 优化目标 → 决策/评估 → 失败边界**。

## 七个能力族

### 1. 输入编码：文本怎样变成模型可计算的单位

- 主实践：01（CH02 Tokenizer）
- 关联章节：CH01—03
- 数据：同一段中英混合文本、emoji、大小写与数字。
- 转换：Tokenizer把字符串映射成不同词表中的Token ID；模型尚未“理解”或生成。
- 目标：这里不是训练目标，而是检查切分规则、信息保留与上下文占用。
- 输出/决策：Token序列与长度。
- 指标：Token数量、未知/拆分情况、同一文本的模型间差异。
- 失败边界：Token更少不自动意味着语义更好；Tokenizer结果不能证明模型知识或推理能力。

### 2. 逐Token生成：从logits到解码与缓存

- 主实践：02、03、04（CH01生成；CH03 logits与KV Cache）
- 数据：提示Token与已生成历史。
- 转换：Causal LM输出每个位置对整个词表的logits；解码器选下一个Token；KV Cache保存历史注意力键值。
- 目标：预训练阶段通常优化下一Token概率；本地实践验证生成链路、张量形状和增量计算。
- 输出/决策：argmax或采样得到Token，再解码为文本。
- 指标：输出可解码、候选概率、重复度、延迟、缓存加速与内存占用。
- 失败边界：能连续生成不等于内容正确或有用；argmax不是“从数据库查答案”；KV Cache提升速度但不提升知识质量。

### 3. 向量判别与结构发现：同一Embedding怎样支持不同答案

- 主实践：05、06（CH04分类；CH05主题建模）
- 数据：带标签影评，或无标签论文语料。
- 转换：Encoder产生Embedding；类别中心/逻辑回归学习判别，UMAP/HDBSCAN/c-TF-IDF形成和命名主题。
- 目标：分类边界与聚类密度是不同目标，Embedding本身不提供最终类别或主题名称。
- 输出/决策：类别标签、置信分数、簇ID、离群点与主题关键词。
- 指标：F1/准确率、混淆样本、主题数、离群率、ARI与组内文档核查。
- 失败边界：相同向量可因决策层不同得到不同结果；聚类参数会改变“主题答案”；关键词不能替代人工阅读组内文本。

### 4. 提示与工具执行：约束模型，以及把模型接到确定性能力

- 主实践：07、08（CH06 Prompt；CH07 Tools/Agent）
- 数据：任务说明、示例、Schema、工具定义与工具观察。
- 转换：提示改变上下文条件；工具链把模型提出的操作交给确定性执行器，再把观察返回模型。
- 目标：提示阶段通常没有参数更新；系统目标是格式遵循、正确调用、观察传递与最终回答闭环。
- 输出/决策：结构化文本、工具参数、执行结果与最终自然语言答案。
- 指标：JSON合法率、Schema/字段正确率、工具计算正确率、观察采用率、最终答案正确率和轨迹完整性。
- 失败边界：one-shot有效不代表所有提示都有效；工具12/12算对也不保证模型采用结果；Agent正确性必须拆成规划、执行、观察和回答。

### 5. 检索与多模态对齐：共同空间只回答“像不像”

- 主实践：09、10（CH08语义搜索；CH09多模态）
- 数据：查询与文档，或图片与候选描述。
- 转换：文本或图文Encoder映射到共同向量空间，检索器按相似度排序。
- 目标：拉近匹配对象、拉远其他对象；不是事实验证，也不是完整回答生成。
- 输出/决策：Top-k文档、图文排名与相似度。
- 指标：Recall@k、Top-1、正确间隔、无答案拒答、否定/干扰描述排名。
- 失败边界：最高相似度不能证明语料含答案；首轮没召回时reranker救不回来；CLIP对not不敏感说明相似度不是逻辑真假概率。

### 6. Embedding训练：loss拟合的是你提供的配对几何

- 主实践：11（CH10 Embedding Training）
- 数据：anchor-positive配对与同batch负样本。
- 转换：更新Encoder，使给定正对更近、其他batch样本相对更远。
- 目标：Multiple Negatives Ranking Loss优化配对矩阵对角线，不理解业务标签含义。
- 输出/决策：新的向量空间，随后仍需检索器或分类器作决策。
- 指标：独立查询Top-1、正确间隔、失败查询与训练loss共同观察。
- 失败边界：错误正对也能让loss下降；训练查询上的拟合不等于独立语义检索改善；假负样本会扭曲空间。

### 7. 任务微调：任务头、标签单位、Adapter与偏好目标

- 主实践：12、13（CH11 BERT微调；CH12生成模型微调）
- 数据：整句分类标签、MLM mask、NER BIO标签、聊天Token或prompt/chosen/rejected偏好对。
- 转换：任务头改变输出形状；冻结决定梯度范围；LoRA训练低秩增量；DPO改变chosen相对rejected的策略margin。
- 目标：分类/Token交叉熵、MLM、SFT下一Tokenloss与DPO相对偏好是不同目标。
- 输出/决策：类别、Token标签、词表分布、生成文本或adapter权重。
- 指标：独立F1与实体跨度、标签mask、参数/梯度探针、固定提示对照、偏好准确率和失败样本。
- 失败边界：冻结层少不保证泛化；错误seqeval形状会制造不可信F1；rank高不保证数据正确；DPO会忠实学习错误偏好。

## 以后研究一个新仓库，只问六个问题

1. **它宣称的最终能力是什么？** 生成文本、返回标签、检索文档、执行动作，还是训练新参数？
2. **数据从哪里来？** 训练/验证/测试是否独立，标签或偏好由谁产生，有没有污染和许可证边界？
3. **代码真正改变什么？** 输入格式、模型权重、Adapter、索引、阈值，还是只改变提示？
4. **优化目标和业务目标是否一致？** loss究竟奖励什么，是否可能“loss下降但产品变差”？
5. **输出怎样变成决定？** 解码、阈值、排序、解析器、工具执行器和后处理分别在哪里？
6. **证据能排除哪些失败？** 是否有独立指标、失败样本、无答案/否定/污染/标签交换等反例，以及明确的未复现资源？

如果这六个问题答不出来，就还不能说“已经理解这个仓库的能力”。

## 总结

这本书最值得迁移的不是某个模型名称，而是责任边界：

- 数据决定系统学到什么信号；
- 模型把输入转换成中间表示或概率；
- 目标函数只奖励它被写明要奖励的东西；
- 决策层把模型输出变成产品行为；
- 指标与失败样本决定我们是否有资格声称能力成立。

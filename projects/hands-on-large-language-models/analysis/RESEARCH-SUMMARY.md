# Hands-On LLM 研究总结与后期使用指南

## 结论先行

这个子项目的第一轮整理已经完成，当前暂时归档；后期按需学习时，可继续作为研究本书和其他 AI 仓库的固定入口。

完成不代表“书中所有大型原模型和完整数据都已复现”，而是代表我们已经完成了足以支持后续使用的基础闭环：

1. 逐章检查了固定版本中 12 个 Notebook 的代码，而不是只阅读 README 或章节标题。
2. 为第 1—12 章建立了 13 个低成本实践，并保留运行结果、失败观察与解释边界。
3. 把 13 个实践归纳为 7 个能力族，形成可迁移的研究方法。
4. 建立了网页入口，把章节、实践、能力地图、运行条件和证据路径连在一起。

## 这个仓库到底是什么

上游仓库是 O'Reilly《Hands-On Large Language Models》的配套教学代码，研究对象固定在提交 `ea3390819997999a51983677b80b3aac4dc50ada`。

它的本质是一本书驱动的 Notebook 教学库：

- 不是可以直接部署的 AI 产品；
- 不是基金、股票或加密货币研究工具；
- 不是一个统一的软件框架或生产服务；
- 主要价值是通过代码练习理解生成、Embedding、分类、聚类、检索、工具调用、多模态和微调。

因此，对我们的意义不是“拥有一个现成应用”，而是获得一条从阅读文本到实践理解、再到迁移判断的学习路线。

## 后期统一使用逻辑

无论继续学习本书，还是研究一个新的 AI 仓库，都沿着同一条判断链：

```text
数据 → 转换 → 目标 → 决策与指标 → 失败边界
```

对应六个必须回答的问题：

1. 它宣称解决什么问题，最终能力到底是什么？
2. 数据、标签以及训练/验证/测试切分从哪里来？
3. 代码真正改变了什么：表示、系统状态还是模型参数？
4. 训练目标或代码目标是否对应实际需求？
5. 模型输出如何变成最终决定，用什么独立指标验收？
6. 当前证据仍不能证明什么，有哪些失败样本和适用边界？

答不出这些问题时，只能说“看过项目”，还不能说“理解了它的能力”。

## 使用这个子项目的推荐顺序

1. 打开[在线学习工作台](https://yydshly.github.io/0823_githubcode_study/projects/hands-on-large-language-models.html)，先确认项目定位和当前完成状态。
2. 从“12章地图”按问题选择章节，不要求机械地从头读到尾。
3. 打开对应实践，先写预期，再查看代码、运行结果和失败边界。
4. 至少修改一个变量，解释结果为什么改变；不能只复制输出。
5. 回到“能力总图”，用五步判断链总结这一章承担的能力。
6. 研究新仓库时复制六问检查表，并把源码路径、运行证据和未验证项记录下来。

## 证据边界

本项目的结论分为三个层级，后期引用时不要混用：

| 层级 | 当前状态 | 可以声称 | 不可以声称 |
| --- | --- | --- | --- |
| 固定源码审计 | 已完成 | 固定提交中的代码流程、模型名、数据源和实现问题 | 上游未来版本仍然完全相同 |
| 代理/低成本实践 | 已完成 | 关键机制在记录条件下可观察、可修改 | 原书大型模型的质量和完整基准已复现 |
| 大型原模型与完整数据 | 暂未完成 | 已记录需要的资源、运行条件和风险 | Phi-3、BLIP-2、MPNet、BERT、TinyLlama 等完整结果已经验证 |

实验中出现的准确率、F1、延迟、loss 或相似度只对相应固定输入、模型、数据切分和运行环境有效，不能直接变成生产质量结论。

## 下载与运行约定

- 阅读网页、README、源码审计和已有 JSON 结果，不需要下载大型模型。
- 低成本复现实践优先使用已经存在的缓存、小模型或合成数据。
- 任何新的模型、数据集或依赖下载都先说明用途、大小、许可证和替代方案。
- 大型资源必须先向用户确认；当前没有为了整理本总结而新增下载或安装。
- 15GB 级或其他明显大型资源默认不下载，只记录完整复现路径。

## 后续怎么继续

当前暂时归档，不需要重新整理框架。后续按学习需求选择增量工作即可：

- 想理解某个概念：进入对应章节和实践，完成一次“预测—运行—修改—解释—迁移”。
- 想提高证据强度：增加独立验证集、反例、失败样本和更严格指标。
- 想复现原书规模：先确认模型/数据下载、GPU、API费用和许可证，再运行原模型。
- 想研究新仓库：直接复用五步判断链与六问检查表，创建新的子项目研究页和证据目录。

第一轮研究的作用，就是让后续工作不再从“这个仓库大概有什么”重新开始，而是从明确问题和可验证证据继续。

# 第 9 章实践：图文相似，不等于图片证明了这句话

本阶段把第 9 章拆成三项不同能力：

1. **CLIP 图文检索**：图片编码器和文本编码器把两种输入放进同一个向量空间，再按余弦相似度排序；不生成文字。
2. **BLIP-2 图片描述**：视觉编码器、Q-Former 和语言模型连接后，从图片生成描述。
3. **BLIP-2 视觉问答**：图片与问题共同作为输入，由语言模型生成答案；可能使用语言先验，也可能产生图中无法证明的内容。

本次低成本实践只运行第一项。这样能先看清“共同向量空间”本身，而不把检索分数和生成答案混为一谈。

## 先读代码，Notebook 实际做了什么

固定上游版本：`ea3390819997999a51983677b80b3aac4dc50ada`。

### CLIP 路径

- 单元 4 从上游 `main` 分支 URL 读取小狗图片与文字描述。
- 单元 7 加载 `openai/clip-vit-base-patch32`；保存日志显示模型权重约 605MB。
- 单元 8—10 把文字切成 Token 并输出 512 维文本向量。
- 单元 11—13 把图片处理成 `[1, 3, 224, 224]`，再输出 512 维图片向量。
- 单元 14 对两类向量做 L2 归一化，以点积得到余弦相似度 0.3315。
- 单元 16—18 将小狗、像素猫和跑车三张图片与三段描述交叉比较；单元 20 用 SentenceTransformers 封装重复同一过程。

```text
图片 -> resize/normalize -> 图像编码器 -> 512维向量 --┐
                                                       ├-> 余弦相似度 -> 排名
文字 -> tokenize ----------> 文本编码器 -> 512维向量 --┘
```

### BLIP-2 路径

- 单元 22 加载 `Salesforce/blip2-opt-2.7b` 的固定 revision；保存日志显示两个权重分片约为 10GB 与 5.5GB。
- 单元 33 由跑车图片生成描述；单元 35 对墨迹图生成描述。
- 单元 38 将图片与问题一起输入；单元 39 追问驾驶该车的价格，保存回答为 `$1,000,000`。
- 单元 40 的“记忆”只是 Python 列表把历史问答重新拼回下一次提示，并不是模型内部永久记忆。

## 源码与证据边界

1. **图片 URL 未固定版本。** Notebook 从上游 `main` 读取三张图片，本次实验改用固定 submodule 中的本地副本，并记录 SHA-256，避免资源漂移。
2. **图片来源信息不完整。** 代码注释只写“AI-generated”，没有生成工具、原始提示或单独许可证说明；上游仓库整体为 Apache-2.0，但不能据此补造缺失的生成来源。
3. **预处理图不是原图。** 单元 12 直接用 Matplotlib 显示已经标准化的 CLIP 张量，并触发数值裁剪警告；它不应被当成忠实 RGB 预览。
4. **变量会被反复覆盖。** `model` 先是 Transformers CLIP，之后换成 SentenceTransformer CLIP，最后又换成 BLIP-2；乱序重跑早期单元可能调用错误对象。
5. **视觉问答可以回答图中没有的事实。** 跑车图片无法证明驾驶成本，单元 39 的 `$1,000,000` 是生成结果，不是视觉证据。
6. **CPU 回退并不等于低成本可用。** BLIP-2 代码在无 CUDA 时仍将 float16 模型放到 CPU；15.5GB 权重和半精度算子使其不适合作为本轮 CPU 基线。

## 我们怎样实践理解

### 问题

CLIP 能否把三张图片与正确描述对齐？如果只在正确描述前加入一个否定词 `not`，与图片的相似度会下降多少？

### 运行前预测

- 三个肯定描述应该分别把对应图片排在第 1。
- 加入 `not` 后，相似度应下降。
- 但肯定句和否定句共享几乎全部 Token，差距可能很小；CLIP 的相似度不是逻辑真假或蕴含概率。

### 固定条件

- 使用上游固定提交中的 `puppy.png`、`cat.png`、`car.png`，不从 `main` 在线取图；
- 使用 Notebook 同款 `openai/clip-vit-base-patch32`，固定 revision `3d74acf9a28c67741b2f4f2ea7635f0aaf6f0268`；
- CPU、同一处理器、同一 512 维归一化向量与余弦相似度；
- 每张图一条肯定描述；受控变化只是在原描述前插入单词 `not`；
- 保存三图×三描述矩阵、每图全部六条描述排名、肯定/否定配对分数与图片哈希。

### 复现

第一次需要缓存约 605MB 的 CLIP 权重。缓存完成后，在项目根目录执行：

```powershell
$env:HF_HOME="$PWD\projects\hands-on-large-language-models\.runtime\hf-home"
$env:HF_HUB_OFFLINE="1"
$env:TRANSFORMERS_OFFLINE="1"
$env:TOKENIZERS_PARALLELISM="false"
.\projects\hands-on-large-language-models\.runtime\venv\Scripts\python.exe `
  .\projects\hands-on-large-language-models\experiments\phase-07-multimodal\run_clip_negation.py
```

结果写入 `results/clip-negation-results.json`。

## 正式结果

| 图片 | 肯定描述分数 | 否定描述分数 | 只加 `not` 后下降 | 六条描述中的位置 |
| --- | ---: | ---: | ---: | --- |
| 小狗雪地 | 0.331496 | 0.298309 | 0.033187 | 肯定第1，否定第2 |
| 像素猫 | 0.346301 | 0.304376 | 0.041926 | 肯定第1，否定第2 |
| 夕阳跑车 | 0.309761 | 0.289038 | 0.020723 | 肯定第1，否定第2 |

三条肯定描述全部正确成为对应图片的 Top-1，复现了 Notebook 的共同向量空间能力。预测的另一半也成立：`not` 会降低分数，但平均只下降 0.031945；三条语义相反的否定描述仍全部排在对应图片的第 2 位，高于另外四条描述。

因此不能把 0.33 理解成“33% 为真”，也不能仅凭一个相似度阈值判断逻辑真假。CLIP 对对象、场景和大量共享词很敏感，但这个小实验表明它对单词级否定的区分远弱于对主体类别的区分。

## 如何读结果

- `affirmativeRetrievalTop1`：三条肯定描述能否各自排到正确图片的第 1。
- `affirmativeMinusNegated`：只加入 `not` 后相似度下降多少；正数表示肯定描述更接近。
- `negatedBeatsAffirmative`：错误的否定描述是否反而比分数对应的肯定描述更高。
- `allCaptionRanking`：同一图片面对三条肯定与三条否定描述时的完整排序，避免只看一个配对分数。

## 你接下来应该怎么改

1. 只把 `not` 改成 `without`，运行前先预测差距会放大还是缩小。
2. 给每张图加入一个“对象正确、场景错误”的描述，检查模型更依赖主体还是背景。
3. 把猫图的透明背景替换成白色或黑色，其他条件不变，观察预处理背景如何影响排名。
4. 增加至少 30 张有清晰标签的独立图片后，再讨论检索准确率；三张示例只能验证机制。

## 理解检查

- 为什么 CLIP 可以比较图片和文字，而普通文本 Embedding 不能直接接收像素？
- 为什么“否定句分数略低”仍不能把相似度解释为真假概率？
- 图片描述和视觉问答都生成文字，它们的文字条件、评测目标和失败来源有何不同？
- 单元 39 的价格答案来自图片证据、模型语言先验，还是无法区分？你会怎样验证？

## 结论边界

这是三张上游示例图的机制探针，不是 CLIP 基准。图片的生成器和原始提示未知；模型卡元数据没有给出许可证字段。BLIP-2 没有在本轮运行，因此本实验只验证图文共同向量空间与否定词敏感性，不验证图片描述或视觉问答质量。

# Kage 能力的使用场景与扩展矩阵

## 判断

Kage 最适合作为一种**沉浸式滚动叙事模式的已完成样本**，而不是直接作为五类业务的共同代码底座。五类场景真正共享的是一条产品能力链：

```text
结构化故事清单
    ↓
镜头 / 章节 / 世界 cue 导演层
    ↓
WebGL 增强运行时 + 语义化 DOM 阅读层
    ↓
质量、动效、无 WebGL 降级
    ↓
可复现审查、发布与运行证据
```

因此，本项目的 P0 不应是继续增加寺院场景细节，而应是把“内容、镜头、场景、质量、降级”解耦，并用原创实验验证这条链。可视化导演台与品牌叙事最接近上游已证明的能力；游戏世界观和文旅展陈需要新增领域系统；AI 叙事生成器必须最后建立在稳定 schema、lint 和人工审查之上。

## 事实、推断与假设

- **已验证事实**：上游能在连续 Three.js 世界中用滚动驱动六个镜头锚点；能混合 DOM 文案、WebP 前景、卡片局部镜头、电影后期；移动低画质、reduced motion 和无 WebGL 阅读 fallback 已在本地浏览器场景中运行。详见 [`upstream-capability-map.md`](./upstream-capability-map.md) 与 [`runtime-report.json`](../evidence/runtime-report.json)。
- **有界推断**：这套模式适合“内容顺序明确、观看节奏可导演、空间氛围重要”的体验；是否提升转化、理解或记忆，需要对应业务实验。
- **尚未验证假设**：配置化 manifest、导演台、游戏状态、展陈内容治理和 AI 生成都不是上游已有功能，必须由独立实验实现和验证。
- **许可边界**：上游未授予 Kage 原始代码或美术的复用/再分发许可。下述方案只能复用抽象模式和公开事实，扩展应使用原创代码、原创主题和权利清晰素材；公开衍生或商业复用前需另行授权。

## 优先级定义

| 级别 | 含义 | 进入条件 |
| --- | --- | --- |
| P0 | 立即验证；构成所有场景的公共底座或最短价值路径 | 不需要真实客户素材；可用原创/合成内容完成；能形成可测验收 |
| P1 | P0 稳定后验证；需要一个明确领域或真实内容合作方 | schema 和 fallback 已稳定；性能与可访问基线通过 |
| P2 | 条件性探索；依赖治理、生成质量或更复杂交互 | 已有审查、版本、来源、回滚与成本机制；有人类责任人 |

优先级不是市场规模排序，而是**技术依赖与验证顺序**。

## 场景深入分析

### A. 品牌叙事：从“定制作品”变成“可换内容的导演模板”

**用户价值**

适用于品牌起源、产品发布、概念空间、年度主题、可持续报告等有明确叙事顺序的内容。Kage 的优势不是让每一页都 3D 化，而是在一个连续世界中保持情绪和空间记忆，让章节切换像镜头调度而不是路由跳转。

**必须新增的产品边界**

```ts
StoryManifest
├─ metadata: title, locale, theme, rights
├─ chapters[]: id, heading, body, cta, media, accessibility
├─ shots[]: position, target, fov, curve, safeFrame
├─ cues[]: chapterId, worldState, domState, audioState
├─ qualityProfiles: high, balanced, low, fallback
└─ reviewStates: deterministic URL / screenshot name
```

这是建议的数据形态，不是上游类型定义。首轮只需足够表达 4 个章节，不要先造通用 CMS。

**最小实验与验收**

- 只修改 manifest，能把 4 个章节的标题、正文、色板、镜头和一个 CTA 换成第二套原创故事；不触碰 renderer 核心。
- CTA 在 WebGL、reduced motion、no-WebGL 三种模式位置一致、可键盘触达、事件只触发一次。
- 390×844 与 1440×900 均无横向溢出、无失败请求；低档主动删效而非仅降分辨率。
- 首屏应先显示可读标题和导航，再渐进增强 WebGL；具体 LCP、交互延迟目标需在部署环境确定，当前不凭本地 headless 数据承诺数值。

**何时不该用**

如果任务主要是高频检索、价格比较、表单填写或后台操作，连续电影镜头会增加认知和性能成本。此时应把 WebGL 缩减为局部 hero，而不是铺满全旅程。

### B. 可视化导演台：优先做“参数审查器”，再做全编辑器

**为什么是 P0**

Kage 已经把镜头、锚点、效果档和定帧状态写成显式数据，但它们散落在 HTML/JS 中。导演台能把这些隐含参数变成团队共同语言，同时为品牌、游戏、文旅和 AI 生成提供同一个验证入口。

**第一版功能**

| 面板 | 最小功能 | 暂不做 |
| --- | --- | --- |
| Chapter rail | 选择章节、显示 scroll progress、跳到 deterministic state | 复杂非线性时间线 |
| Camera inspector | position/target/FOV、safe frame、曲线预览、reset | 完整 Maya/Blender 级 3D 编辑 |
| Cue inspector | 可见层、色板、环境强度、CTA 状态 | 任意 shader 节点图 |
| Quality switcher | high/balanced/low/reduced/no-WebGL | 自动云设备农场 |
| Export | schema 校验后导出 JSON、版本号、变更摘要 | 直接发布生产 |

**最小实验与验收**

1. 选中章节 2，拖动摄影机位置或输入 FOV；预览实时更新。
2. 导出 JSON，刷新后导入能得到同一 deterministic screenshot。
3. 超出 safe frame、镜头穿过地面或 target 过近时给出 lint，而不是静默保存。
4. runtime 只暴露版本化诊断快照；导演台不直接持有 Three.js scene 对象。

**长期扩展**

之后才考虑 shot diff、评论锚点、多人审阅、云端截图矩阵和与 DCC 工具交换数据。导演台的目标是减少“改一个数再刷新”的沟通成本，不是复制专业 3D 软件。

### C. 游戏世界观：把线性镜头用作 onboarding，不把它当完整 game loop

**适合的子场景**

- 游戏开场的可跳过世界观序章；
- 主菜单或 codex 中的 3D lore walk；
- 轻探索网页 ARG；
- 角色/地点选择前的空间化导览。

**必须新增**

- `NarrativeStateMachine`：发现、选择和后续 cue 的状态图；
- `InteractionRegistry`：热点、输入、焦点、可访问等价操作；
- 碰撞与受限移动，或明确维持轨道式相机；
- 音频、字幕、暂停、跳过、存档和恢复；
- deterministic fixture，使每个选择路径可以自动回放；
- 资源流送与显存预算，而非一次构建全部世界。

**最小实验**

一个原创空间中只放 3 个 lore 热点和一个二选一。用户可选择“自动导览”或“检查模式”；选择改变下一章节的灯光/文案，但不能导致内容不可达。DOM transcript 始终能查看全部必要 lore。

**判退条件**

若验证需要战斗、复杂 NPC、多人同步或大地图自由移动，应直接采用成熟游戏技术栈；Kage 模式最多作为叙事前端，不应承担核心游戏系统。

### D. 文旅展陈：真实内容治理比画面升级更优先

**目标用户不止游客**

策展人要能核对来源，文化顾问要能审校表达，现场运维要能恢复设备，游客则需要多语言、字幕、键盘/触控和低刺激模式。只完成视觉导览远远不够。

**内容模型必须多出的字段**

- `source / citation / date / reviewer`：每条史实的出处与审核责任人；
- `representationType`：实拍、扫描、推测复原、艺术演绎、生成图必须区分；
- `rights / territory / expiry`：素材权利与到期策略；
- `locale / transcript / alt / audioDescription`：多语言与替代内容；
- `offlinePolicy / resetPolicy`：现场断网、空闲重置与故障页。

**最小实验**

使用虚构展品并醒目标注“技术验证素材”，做三站 kiosk：中英切换、键盘和触控均可走完、60 秒空闲回首页、断网不丢内容、无 WebGL 显示等价图文。只有这些基础通过后，才引入真实地点和机构素材。

**风险门**

任何真实遗产叙事都必须有领域责任人批准；生成图不能作为史实证据；空间重建中的推测部分要可见标注。Kage 的“受日本寺院启发”不能自然升级为某一真实寺院的数字孪生。

### E. AI 叙事生成器：生成“受约束草稿”，不生成可执行网站

**正确输出层级**

AI 最安全且最有价值的输出是经 schema 约束的 `StoryManifestDraft`，而不是 HTML、shader 或任意 JavaScript。renderer、组件、质量策略和 fallback 都应来自白名单运行时。

**建议流水线**

```text
brief
  → planner：受众、目标、章节弧线
  → structured draft：只生成 schema 字段
  → lint：长度、镜头安全框、资源权利、性能预算、可访问字段
  → preview：原创 runtime 的 deterministic state
  → human edit / approve
  → versioned publish；可一键回滚
```

**最小实验与验收**

- 输入同一 brief 两次可以产生不同草案，但每个草案都能通过 JSON schema 或明确失败，不能输出半可执行代码。
- 缺少 `alt`、来源、权利或 fallback 文案时阻止发布。
- 每个章节限制可用组件、粒子和素材数量；超过预算时 lint 直接指出字段。
- 生成结果必须经过人工确认；模型不能拥有发布权限。
- 对引用的素材保留来源、模型、生成时间、编辑人和许可元数据。

**为什么是 P2**

在 manifest、导演台、lint、质量和回滚未稳定前加入 AI，只会放大结构漂移。先让人能可靠编辑和验证，再让模型生成同一种受约束结构。

## 跨场景公共扩展路线

### P0：建立独立、可验证的叙事内核

| 模块 | 职责 | P0 验收 |
| --- | --- | --- |
| `StoryManifest + schema` | 章节、镜头、cue、内容、fallback 的单一真源 | 两套原创 manifest 可无代码切换；非法字段有明确错误 |
| `CameraDirector` | scroll/time → position/target/FOV；窄屏 safe frame | 任意章节可 deterministic 定帧；曲线与 DOM 锚点不靠数组位置暗合 |
| `CueBus / WorldAdapter` | 章节进入、离开和 focus 反馈 | 世界主题可替换；DOM 不直接操作场景内部对象 |
| `QualityGovernor` | high/balanced/low、动态 DPR、效果预算 | 记录选择原因与当前档；移动删效可观测；用户可覆盖 |
| `AccessibleSurface` | DOM 阅读、导航、reduced、no-WebGL | 三种模式共享内容；键盘可完成主旅程 |
| `Review Harness` | 定帧 URL、状态快照、桌面/移动截图 | 每个章节和降级状态可复现；无失败请求 |

### P1：把内核变成团队生产系统

- 可视化导演台的 camera/cue/quality inspector；
- 本地化、内容来源、权利和无障碍字段；
- 受限热点与轻量叙事状态机；
- 音频 cue、字幕与用户静音/暂停；
- 真实设备性能矩阵和视觉回归；
- 只读运行诊断、错误分类与预期 fallback 监控规则。

### P2：在治理之上增加生成与规模化

- AI brief planner 与结构化草案；
- 白名单素材/组件推荐，不执行生成代码；
- 权利与来源检查、成本记录、缓存和版本回滚；
- 多项目模板库、远程审阅和批量设备截图；
- 经真实数据证明后，再探索个性化章节顺序或自适应镜头。

## 关键风险矩阵

| 风险 | 哪些场景最敏感 | 早期信号 | 控制措施 |
| --- | --- | --- | --- |
| 原始代码/美术无复用许可 | 全部，尤其品牌与公开展陈 | extension import 上游文件、使用其 WebP/字体、照抄 shader/坐标 | upstream 只读隔离；clean-room 实现；素材账本；发布前法律/许可审查 |
| GPU 与电量成本 | 品牌、游戏、kiosk | 桌面 headless 已出现 7.7–23.9 fps 观察值；多 WebGL 上下文 | 实机 profiling；一画布优先；效果预算；balanced 默认；静态 fallback |
| 内容被视觉淹没 | 品牌、文旅 | 用户记得氛围但找不到事实/CTA | DOM 内容优先；可跳过；目录与进度；CTA 不依赖 3D 命中 |
| 文化或事实误导 | 文旅、AI | 生成图未标注、推测复原被当史实 | 来源必填、representationType、领域审校、发布门 |
| 镜头不适与无障碍缺口 | 全部 | reduced motion 仍有连续环境动效；键盘路径不完整 | 效果级 motion registry；暂停；键盘/屏幕阅读器审计；等价 transcript |
| 配置化变成“万能系统” | 导演台、AI | schema 快速膨胀、每个项目都加特例 | 保持少量白名单 primitives；用两个真实样例验证抽象后再扩字段 |
| AI 结构/资产漂移 | AI、品牌 | 生成任意代码、预算超限、来源缺失 | JSON schema、lint、白名单、人工批准、可回滚版本 |

## 研究决策门

| Gate | 要回答的问题 | 通过标准 | 未通过时 |
| --- | --- | --- | --- |
| G0：独立性 | 扩展是否完全不依赖 Kage 原始代码/素材？ | 静态扫描无 upstream import/URL；原创主题；许可清单完整 | 停止公开演示，替换实现/素材 |
| G1：结构化 | manifest 是否真能驱动第二套故事？ | 只改数据完成第二主题，DOM 与 WebGL 同步 | 缩小 schema，不继续做导演台 |
| G2：体验完整 | 桌面、移动、reduced、no-WebGL 是否都能完成主旅程？ | 内容可达、导航可用、无失败请求、状态可复现 | 修复基础体验，不新增场景 |
| G3：性能 | 目标设备是否在预算内？ | 在明确设备矩阵和测量方法下达标 | 默认降档、删效或改成局部 WebGL |
| G4：领域价值 | 真实用户是否比普通图文页更理解/记忆/完成任务？ | 为对应场景设 A/B 或任务指标并得到正向证据 | 保留为局部视觉模块，不平台化 |
| G5：生成治理 | AI 草案是否可验证、可追溯、可回滚？ | schema/lint/人工门/来源记录均成立 | AI 仅做文字建议，不进入 runtime |

## 对我们的意义

1. **它给出了高质量结果的完整参考，而不是现成依赖。** 我们可以用它定义“连续镜头、章节节奏、移动删效、fallback、定帧审查”应该达到的完成度。
2. **它暴露了作品到平台之间缺失的中间层。** 最有价值的研发不是再做一个单文件特效页，而是建立 manifest、CameraDirector、CueBus、QualityGovernor、AccessibleSurface 和 Review Harness。
3. **它适合先成为内部导演与验证工具，再成为外部产品。** 导演台能服务多个主题；品牌叙事是最短业务验证；游戏和文旅在公共底座稳定后进入；AI 最后接入。
4. **它让许可边界成为架构约束。** clean-room 并非附加说明，而是促使我们把文化主题、素材和实现替换成真正可拥有、可维护的原创系统。
5. **它提供了明确的止损条件。** 若第二主题无法只改数据、fallback 不等价、真实设备性能不达标或用户任务没有改善，就不应继续把它扩成通用平台。

首轮扩展的推荐交付因此是：一个原创主题的配置化叙事实验台，加一套最小导演/诊断入口，并以桌面、移动、reduced motion、no-WebGL 四个状态作为共同验收面。它同时服务 P0 的品牌壳层和导演台，又不会提前背负游戏、文旅或 AI 的领域复杂度。

# R14 · 素材质量门禁

## 目的

在 Codex 编写网页之前判断素材能否真正承担本次作品的主体、环境和连续状态责任。门禁解决的是“有文件但素材不够好”的问题，不重复素材来源选择。

## 决策

- `ready / low`：体验不依赖外部关键素材，可以使用 Three.js、Shader、CSS 和语义 DOM 直接构建。
- `ready / medium`：已有 ChatGPT、用户提供或授权素材与所需模态、融合方式和最低质量匹配。
- `needs-codex-assets / high`：关键素材缺失，或只有 MiniMax 的 L2 候选，任务在 Codex 编码前停止并生成明确素材请求。

## 素材请求内容

每项请求保存素材角色、模态、最低质量、推荐来源、视觉职责、连续性、融合方式和可见验收证据。真实 GLB 等不能由图片替代的资产只能由用户或授权来源提供。

## 当前边界

R14 负责诚实停止并把请求显示在工作台。补齐素材后从当前任务继续执行属于 R15；在 R15 完成前，门禁不会假装自动恢复。

## 验收结果

- 程序化主题不会被错误拦截。
- 可信项目素材可以通过。
- MiniMax L2 关键主体会被拦截。
- 真实模型缺失会给出用户或授权素材请求。
- 被拦截任务不会进入 Codex authoring 阶段。

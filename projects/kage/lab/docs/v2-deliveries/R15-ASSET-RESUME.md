# R15 · 素材接力与任务恢复

## 目的

当 R14 因关键素材不足而停止时，允许用户或当前 Codex / ChatGPT 对话补充真实文件，并从已经确定的 Codex 构建边界继续，而不是重新调用模型理解想法、重新选择参考或重新规划方向。

## 持久化检查点

任务在素材门禁前保存完整的 `DedicatedCodeRequest`：原始目标、seed、质量、run、候选方向、V2 Creative Contract、参考摘要和当前候选素材。它是恢复构建的唯一检查点。

## 恢复流程

1. 工作台显示门禁生成的具体素材请求。
2. 用户选择 PNG、JPEG、GLB、音频或视频文件；现有导入器验证扩展名、文件签名和 20 MB 上限。
3. 工作台把缓存素材 ID 绑定到当前任务的具体 `requirementId`。
4. 服务器只接受真实存在、来源为 `user-supplied` 的本地缓存素材。
5. 再次运行素材质量门禁；仍有缺口就继续暂停。
6. 门禁通过后任务状态回到 `assets / running`，随后直接进入 `authoring`、浏览器评审和最终结果选择。

## 性能与诚实边界

- 等待素材的时间不触发模型调用。
- 恢复时不重新执行 planning、interpretation 或 candidate selection。
- 用户确认文件可以进入构建，但仍不等于自动获得发布权利或视觉质量；最终网页必须通过浏览器截图验收。
- 文件模态错误时不会通过门禁，例如需要 GLB 时上传 PNG 仍会继续暂停。

## 验收结果

自动测试覆盖“MiniMax L2 主体被阻断 → 导入合法 PNG → 绑定 hero-product → 直接恢复 Codex 构建 → 视觉验收完成”。测试同时断言模型理解只调用一次，恢复过程中没有新增 planning 调用。

# R13 · Codex 执行包

## 目的

Kage 的核心仍是技术探索，但 V2 不再要求本地规则独立完成创意网页。研究库负责把优秀案例中验证过的构图、动效、素材与交互逻辑沉淀成边界；Codex 负责在这些边界内完成素材协调、网页编码、运行验证与局部精修。

## 两层合同

- 完整 Creative Contract：保存参考来源、评分、能力定义和研究证据，用于解释、追溯和后续扩展。
- Codex Execution Brief：只保留本次执行需要的目标、叙事状态、可借鉴原则、素材职责、渲染路线、交互语义、验收项和停止条件。

生成、增量修改、视觉精修和最终验收统一读取执行包；完整合同继续随构建报告存档，不在每个模型阶段重复传输。

以梦境记录目标为样本，完整合同为 8,315 字符，执行包为 4,382 字符，模型边界输入减少约 47%。该数字随主题变化，但回归测试要求执行包始终显著小于完整合同。

## 边界

- 执行包不是页面模板，叙事节点不是固定章节。
- Codex 可以创造具体构图、材质语言和实现方式，但不能增加未选择的能力或忽略必需素材证据。
- 一次只创作一个候选，并遵守合同中的时限与精修次数。
- MiniMax 仍是候选素材来源；主体连续性不足时，由 Codex/ChatGPT 生成或选择更可靠的视觉锚点。

## 阶段结论

本阶段验证的不是“去掉 Codex”，而是建立稳定的 Codex 调度接口：让研究成果真正缩小执行搜索空间，同时保留生成独特网页所需的创造自由。

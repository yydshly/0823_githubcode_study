# R26：语义视觉质量门与最优案例复验

## 回到项目目标

项目目标仍是：用户描述一个期望的想法，系统按需生成或选择素材，构造独立且可运行的 Three.js 网页，并通过真实浏览器证据与视觉模型迭代到可接受成品。案例库只保留少量能力基线和每个目标的最优结果。

## 本轮发现

`dedicated-ba4e9d10caaa-depth-field` 是经过模型生成、素材融合和多轮精修的完整结果，应该作为时装方向的最优案例，而不是被未精修的中间运行替代。

- 原机械门禁只记录文字矩形的重叠数量和最大比例。
- Grid 拉伸的导航链接布局盒与离场文案相交时，会被误报为视觉碰撞。

## 架构判断

- 运行未就绪、Canvas 缺失、浏览器错误、横向溢出和时间线不变化继续作为结构缺陷。
- 按钮、链接与正文的真实绘制区域碰撞继续触发修订。
- 标题式创意叠层记录为 `editorial-overlap` 观察项，不做机械扣分，交给四张截图和视觉模型判断阅读顺序与构图意图。

机械门禁负责证明页面没有结构性失败，视觉模型负责判断构图是否优秀；两者不能互相替代。

## 已实现

- 浏览器采集同时输出原始碰撞、阻断碰撞、编辑式叠层和最大阻断比例。
- 文字碰撞改用 Range 的实际绘制内容边界，不再直接使用可能被 Grid/Flex 拉伸的布局盒。
- 评审结果增加非扣分 `observations`，与必须修复的 `findings` 分离。

Codex 5.6-sol 精修提示词已同步：`editorial-overlap` 不能单独成为修改理由，必须结合首屏、中段、终点和移动端截图判断。

## 最优案例修复与证据

真实复验定位到 Hero 的 `Scroll / Material dissolves` 在离场时穿过固定 Logo。该问题不是 Three.js 素材边界，而是 DOM 状态导演缺少离场状态。

- 为提示增加基于 `--page-progress` 的提前淡出和轻微上移。
- 保持透明服装素材、深度场、粒子、文字主体和背景融合方式不变。
- 桌面 opening/middle/final 与 390px reduced-motion 四状态均 ready。
- 四状态 Canvas 数量均为 1，横向溢出均为 0，碰撞均为 0。
- 结构评审由 86 / revise 提升到 100 / pass。

最终证据保存在 `generated/runs/dedicated-ba4e9d10caaa-depth-field/visual-review.json`。

# V2 R31：受约束的端到端生成验证

## 目标

用一个未使用过的明亮手工主题验证当前主链路：想法 → 创意合同 → Codex 专属代码 → 编译 → 浏览器验收。主题是“日光木版套印工坊”，要求同一张和纸随滚动依次形成木版压痕、靛蓝海浪和朱红飞鸟，最终导向预约行动。

本轮不是继续扩充能力，也不是制作多个候选。验证重点是：研究沉淀能否缩小模型自由范围，同时保留与既有暗色、中央主体案例不同的创意方向。

## 路由纠错

第一次任务 `job-1bf761637aad48ba` 没有进入代码生成。合同把“一间日光木版套印工坊”误判为素材主体，并错误要求 MiniMax 生成透明主体图，素材门禁因此阻断。

修正后：

- 开场句中的“一张悬浮在木桌上、尚未落墨的和纸”成为真正视觉主体；
- 纸张、木版、套印、压印和墨层被识别为 `material-transformation`；
- 该主题选择程序化材质路线，不调用 MiniMax；
- 增加回归测试，防止材料变化主题再次被路由为无关图片资产。

## 有效运行与耗时

第二次任务 `job-bdba46e9a1cdf0d8` 产出原始运行 `dedicated-8607ba931ee4`：

| 阶段 | 耗时 | 结论 |
| --- | ---: | --- |
| 创意合同 | 10 ms | 已不是性能瓶颈 |
| Codex 作者阶段 | 约 221.6 s | 内部发生 2 次编译尝试；第一次约 100 s 后重试 |
| 视觉验收与自动精修 | 约 130.4 s | 验收给出明确问题，但自动精修超过 90 s |
| 总耗时 | 约 352 s | 慢点来自模型作者重试与精修，不来自本机编译 |
| 本地编译 | 395 ms | 工程构建不是主要等待来源 |

这解释了工作台此前“长时间像没有动作”的体感：重试次数和精修阶段没有被充分暴露，用户只能看到笼统的 authoring/reviewing 状态。

## 视觉验收与有界修订

自动验收初次给出 48 分，主要问题是：朱红形状像椭圆占位、海浪与飞鸟关系不成立、移动端 URL 简化模式没有影响 CSS，以及 WebGL 失败时只有空背景。

没有重新让模型开放式探索，而是在原始 bundle 上完成一次有界修订：

- 保留同一张纸、三次落版和单一滚动时间线；
- 把海浪移到纸张下半部，把朱红改成可识别的三只飞鸟；
- 去除终场大面积浅色遮罩，恢复靛蓝和朱红对比；
- 增加 SVG 静态纸张作为 WebGL 失败后的主题回退；
- 将 SDK `context.reducedMotion` 映射为根节点 class，使 `motion=reduce` 不依赖操作系统媒体查询；
- 把这一要求写回 Codex 作者契约并加入测试。

最终一致运行：`dedicated-7b4cae3ee35e`，源码 17,731 bytes，编译 391 ms。

## 浏览器证据

- 桌面：1440 × 900，进度 `0 → 0.5 → 1`，滚动范围 1800 px，无横向溢出；
- 移动端：390 × 844，URL `motion=reduce` 生效，过程区隐藏、滚动范围归零、预约按钮在首屏；
- WebGL 强制失败：静态和纸、海浪、飞鸟、标题与预约按钮仍可见；控制台仅出现预期的 WebGL context 创建失败信息；
- 截图位于 `.artifacts/r31-woodblock/`。

## 结论与停止条件

主链路已经证明可以在没有 MiniMax 素材的情况下，把一个新的明亮手工主题生成成可运行、可滚动、可降级的专属网页。它证明 V2 的约束路线有效，但当前视觉完成度仍低于精选案例库中最强作品，因此本轮保留为运行与研究证据，不提升为精选案例。

本轮已经先完成工作台作者阶段的可观察性修复：任务历史会显示当前第几次/最多两次尝试、已耗时、单次硬上限，以及第一次输出未通过本地编译时的失败摘要。进度更新失败不会反向中止一个有效构建。

下一步不应再制作新案例。剩余的性能动作是拆开“视觉验收”和“自动精修”：验收已经给出可执行问题时先停在可见的 `review-required`，由一次明确的有界修订继续，而不是默认再消耗一轮长模型调用。

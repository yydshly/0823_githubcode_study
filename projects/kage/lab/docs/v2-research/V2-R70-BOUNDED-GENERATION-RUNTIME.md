# V2 R70 · 有界生成运行时

## 目标

解决“任务像在无限执行”的工程问题，不增加创意模板、不生成新案例，也不降低以最终网页质量为准的第一目标。

## 已完成

- 每个任务持久化 `authoringAttempts / recoveryAttempts / refinementAttempts`，三类自动动作上限均为 1。
- 单次服务器任务拥有独立五分钟截止时间；模型、素材与视觉阶段的超时会受剩余总预算约束。
- 服务若在 `authoring` 阶段重启，只恢复已经保存的候选；没有候选则明确失败，不重新理解 brief、选择素材或调用 Codex。
- 服务若在 `refining` 阶段重启，保留可运行候选并转为 `review-required`，不再次调用视觉模型。
- 终态任务、404 和 410 任务停止网络轮询；新任务 ID 会重新启用轮询。
- 旧任务中的过期 V2 Creative Contract 会在读取时迁移为当前合同，避免历史最终案例因 Schema 演进变成 404。
- 超时后既有 `taskkill /T /F` 子进程树终止逻辑继续保留。

## 验收

- `npm.cmd test`：68 个测试文件、287 个测试通过（加入旧合同迁移后最终为 288 个，见当次完整回归）。
- `npm.cmd run build`：TypeScript 与生产构建通过。
- 浏览器恢复历史完成任务后，清空请求日志并等待 2.6 秒，`/api/creative/jobs/*` 请求为 0。
- 发酵案例继续保持同一主体、滚轮语义状态、数值与建议同步，不受运行时修正影响。

## 停止边界

R70 到此停止。后续 R71 只整理构建警告、案例分层、研究记录和提交基线；在 R71 完成前不启动新模型任务。

# V2 R46 · 产品驱动的自适应体验结构

## 结论

页面结构不能默认等于“开场 / 中段 / 结尾”三屏。V2 现在先判断产品体验类型，再由内容和交互关系派生语义状态、节奏和验收位置。语义状态是同一体验中的时间或交互锚点，不等于 DOM 页面数量。

## 结构模式

| 产品目标 | 结构模式 | 组织原则 |
| --- | --- | --- |
| 简单活动或编辑页面 | `editorial-flow` | 按信息密度形成连续版面，不补空章节 |
| 单主体连续变化 | `continuous-canvas` | 同一画布持续存在，状态只改变主题相关属性 |
| 产品发布或空间探索 | `guided-sequence` | 节点数量与时长由解释任务和空间关系决定 |
| 地图、数据与选择工具 | `interactive-field` | 保留同一工作区，选择改变状态，不一站一页 |
| 诊断、配置与操作任务 | `task-flow` | 以选择、检查、验证和行动组织界面 |

## 当前木版案例判断

- 原运行 `dedicated-7b4cae3ee35e`：程序化结构可运行，但没有真实成品素材，三段式结构明显，只保留为技术原型。
- 素材增强版 `dedicated-woodblock-asset-r32`：纸墨质量明显提升，但仍把三个工序集中在固定中段，产品节奏不足。
- 当前版 `dedicated-woodblock-adaptive-r46`：使用同一张高质量和纸素材和同一 Three.js 画布，按和纸就位、木纹压痕、靛蓝落版、朱红套色、作品完成五个非均匀状态连续推进。

当前版质量判断为“可公开的精修案例”，不是无条件精选：主题、素材连续性、行动和移动端已达标；仍可继续提升木版压下的触觉反馈、文字卡与纸面关系以及字体精度。

## 验证

- 合同、工作台和 Codex Execution Brief 都携带 `experience.structure`。
- 素材与过程状态由合同派生；作者提示明确禁止把 beats 机械转换为页面。
- 浏览器验收按实际 beats 生成 5 个桌面关键状态和 1 个移动端状态，不再固定四屏。
- 230 项测试通过，生产构建通过，案例、案例库和工作台均返回 HTTP 200。

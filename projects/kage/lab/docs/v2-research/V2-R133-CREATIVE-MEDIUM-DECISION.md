# V2 R133 · 创作媒介决策收口

## 进入条件

- Request revision：R133。
- Entry mode：revision-led。
- 前置证据：R131 已证明代码原生对象场可承担声音路线；R132 已证明生成图可承担视觉记忆点、代码可承担互动因果。
- 本轮问题：两种能力仍靠单次案例的人工作者选择，没有成为“想法 → 专属网页”主链中的明确决策。因此新主题仍可能被历史 renderer、关键词或参考案例带回同一种页面语法。

## 阶段目标

在不改动 V1、工作台后台、模型供应商和既有交付页的前提下，为 V2 直接创作增加一个可解释、可测试的 `CreativeMediumDecision`：

1. 根据用户硬要求与主题责任选择一种首选媒介；
2. 在生成图、真实/有出处媒体、Three.js 空间模型、WebGL 程序视觉、代码原生图形之间做内容驱动的选择；
3. 只保留一个失败回退方案，不能把回退解释成第二批素材；
4. 把决策、素材责任和真实性边界传入作者包与 `DirectCreativeRun`；
5. 保持参考案例为正向建议，不让案例、关键词或历史样式覆盖用户要求。

本轮不生成新案例，不调用图像模型，不连接工作台后台，不新增供应商，也不扩展研究库。

## 设计契约

### 输入优先级

1. 用户当前任务的 `hard` 指令；
2. 通用质量与真实性门；
3. 主题中可验证的内容信号；
4. 参考案例与推断建议。

后两项只能影响建议和排序，不能形成新的全局禁止项。

### 候选媒介

| 路线 | 应承担的责任 | 典型命中 | 不应承担 |
| --- | --- | --- | --- |
| `generated-image` | 主题专属的关键氛围、虚构空间或视觉记忆点 | 非事实场景、自然/叙事氛围、需要独特主视觉 | 真实地图、真实数据、可验证产品事实 |
| `grounded-real-media` | 真实地点、纪实主体、来源可说明的产品或资料 | 城市地图、档案、真实场所、商业产品 | 伪造为真实的生成内容 |
| `threejs-spatial` | 可观察的空间、结构、部件关系和直接操控 | GLB、拆解、空间巡视、对象结构 | 只为“有 3D 感”而增加无意义模型 |
| `webgl-procedural` | 材质、光照、几何或状态变量的实时因果变化 | 釉色、薄膜、流场、光学状态 | 仅因出现“图表/关系图”关键词而使用 shader |
| `code-native` | 精确排版、数据、路径、图表与轻量互动 | SVG、Canvas 2D、DOM、编辑排版、证据图 | 用低质量 CSS 图形冒充关键产品素材 |

### 决策输出

- 一个 `preferred` 路线；
- 一个不同的 `alternative`，仅在首选媒介不可用时启用；
- 明确的命中信号、理由、置信度和真实性边界；
- 零到若干素材责任，每项说明角色、视觉职责、可见证据和是否必需；
- 与运行时媒介、作者包和素材计划保持一致。

### 有界执行

- 只实现一个决策模块及其最小主链接口；
- 不自动生成素材；
- 不启动第二个创意方向；
- 不改变直接创作的一次素材批次、一次构建、最多两次确定性修复、最多一次视觉精修预算；
- 决策失败时使用声明的回退或诚实停止，不循环重选媒介。

## 主旅程

1. 读取 `V2CreativeContract` 中的 brief、用户指令、资产、体验方向与真实性要求。
2. 生成内容相关候选并选择一个首选、一个回退。
3. 以首选媒介推导视觉野心与素材责任。
4. 将同一决策写入 `CodexExecutionBrief`、作者包和 `DirectCreativeRun`。
5. 运行单元、协议与 V2.5 回归，证明决策不会被历史模板或单一关键词改写。

## 兼容边界

- `CreativeContract` 保持兼容，不为历史合同增加必填字段。
- 历史归档的 `DirectCreativeRun` 仍可解析；新建 V2 运行必须携带媒介决策。
- V1、工作台后端、Minimax 路由、Figma、既有交付页和案例内容不在本轮修改范围。
- 如果决策进入运行身份，旧截图或旧 bundle 不能替代新决策的最终证据。

## 停止条件

上述六项全部通过即关闭 R133。阶段完成后没有以“继续收集案例”或“再生成一个页面”作为隐藏尾项；下一阶段是否调用该能力生成新案例，必须重新以整体目标和明确小阶段立项。

## 实现结果

- 新增 `creative-medium-decision.ts`，输出一个首选路线、一个可选失败回退、素材职责、命中信号和真实性边界。
- `CodexExecutionBrief` 只计算一次媒介决策，并将同一对象传给 `VisualAmbition`；不再让 legacy renderer 独立决定新运行的主媒介。
- 新增 Direct Creative Protocol V3：新作者包、运行 ID、素材批次和媒介决策指纹绑定；V1/V2 保持旧推导与旧身份，可继续重建冻结案例。
- `raster-image` 成为正式视觉媒介，生成图和真实媒体不再被错误记录为 `dom-css`。
- 最终候选在 V3 中必须使用当前 run ID；媒介改变会改变运行身份，旧候选与旧证据不能附到新决策。

## 最终验证

- `npm run test:v2.5`：22 files / 137 tests passed。
- `npm run build`：passed。
- `npm run build:pages`：passed；保留六个既有运行时绝对素材路径警告，本轮未新增该问题。
- `npx playwright test e2e/v2-composer.spec.ts`：4/4 passed，覆盖桌面作者包、390px、能力选择和输入漂移停止。

R133 已阶段性关闭，无剩余未完成项。它没有生成新页面；它把 R131 的代码原生路线与 R132 的生图路线从人工经验升级为下一次想法创作可以直接复用的产品决策能力。

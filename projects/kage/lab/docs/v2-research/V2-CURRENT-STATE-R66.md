# V2 当前项目状态（R66）

## 第一目标

用户只描述想看到的产品与变化。Kage 在内部理解业务、选择优秀参考原理、决定素材与 DOM / Canvas / Three.js 职责，调用 Codex 构建专属网页，并用浏览器证据决定它是最终网页、待素材结果还是待评审结果。

这里的产品不是 Three.js 模板生成器。Three.js、图片、连续媒体、GLB、CSS 与语义 DOM 都只是按最终效果选择的实现手段。

## 已形成的主链路

```text
用户想法
  → 意图与来源边界
  → V2 Creative Contract（参考原理、结构、视觉锚点、交互因果、停止条件）
  → 素材职责与质量门禁
      ├─ 已满足：进入 Codex 专属构建
      └─ 未满足：复制精确素材任务 / 上传本地素材 / 恢复同一 Job
  → 独立代码 bundle
  → 编译与沙箱运行
  → 自适应浏览器状态采样
  → 机械门禁 + 独立视觉验收
      ├─ 通过：最终网页，可进入精选案例
      ├─ 可有限修复：最多一次证据驱动精修
      └─ 超出范围：停止为 review-required，不无限重试
```

## 当前能力结论

- “想法 → 可运行专属网页”已经实现并在多个不同主题上运行过。
- 优秀案例研究已经进入参考证据、创意方向、能力选择与差异化约束，不只是研究页面展示。
- 页面结构不是固定三屏或四屏；状态数和检查点由产品过程与交互模式推导。
- 素材、程序化 Three.js 和模型生成不再被预先禁止；但低质量素材、占位几何和不可信业务证据不能被称为最终结果。
- 持久 Job、耗时阶段、错误原因、有限精修和可恢复素材门禁已经形成工程闭环。
- R65 保留榫卯与折叠灯两个最终案例；R66 不增加案例，只补齐通用流程与最终效果规则。

## 尚未完成

1. **图片能力仍非完全内嵌。** MiniMax 可以作为候选适配器，但质量不足时需要 Codex/ChatGPT 外部生成或用户素材；R66 已让这个过程可操作、可恢复，但没有伪装成全自动 API。
2. **最终审美仍需模型与人共同判断。** 自动门禁能拒绝主体错位、调试残留、素材边界、交互无因果等明确缺陷，但不能保证每次创意都优秀。
3. **尚缺一次正式 Beta 新目标验收。** 需要从工作台输入一个从未使用的新目标，限制为一个作者候选、最多一次精修，记录总耗时和最终三态结论。
4. **V2 尚未独立发布。** 本地生产构建已通过；公开静态站不能执行本机 Codex 服务，发布时必须清楚区分静态能力演示与本地完整生成。
5. **构建体积有已知提醒。** `experience` chunk 超过 500 kB，当前不影响 Beta 正确性，后续作为性能任务处理，不阻塞本阶段。

## 下一阶段（只做一轮）

1. 选一个新目标，运行真实工作台主链路，不复用旧案例主题。
2. 若缺素材，使用 R66 操作层补齐并恢复同一 Job；不新开任务。
3. 浏览器按产品需要采样状态，不固定屏数；桌面、390px、减弱动效必须覆盖。
4. 只允许一次证据驱动精修；仍未通过则停止为 `review-required`。
5. 形成一份 Beta 验收记录。只有最终通过的版本才进入案例库，然后再决定是否发布 V2。

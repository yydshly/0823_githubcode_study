## 验证 Brief

> 为一款帮助人保存气味记忆的产品设计沉浸式网页。开场是一只雾气凝结的玻璃记忆瓶；滚动时气味被分解为雨后泥土、旧书纸张和晒过的棉布三层空间，指针或触摸改变混合比例并同步更新记忆文字；最后三层重新汇成一只可保存的气味标本，行动为“封存这段记忆”。画面温暖、克制、真实，像自然历史博物馆与香水实验室的结合；不要霓虹科技风，不要用无意义粒子充当主体。

## 本轮发现并修复的主链问题

1. **风格词误判结构**：`博物馆`原本会把页面误路由为 `spatial-exploration`。现已让它只承担视觉语气，结构改由用户明确的交互和叙事动作决定。
2. **模型擅自升级素材依赖**：远程 EffectSpec 曾增加合同未要求的 GLB，导致任务错误阻塞。现在 V2 合同是外部素材模态的唯一边界。
3. **淘汰素材仍进入构建**：门禁只接受 ChatGPT 主素材，但旧恢复逻辑仍把 MiniMax L2 候选传给 Codex。现在恢复构建只携带 `acceptedAssetIds`。
4. **素材引用误判**：`continuity` 中的 `ui` 曾被裸正则误判为 UI 素材证据，已修正。
5. **触摸并不等于鼠标移动**：生成页 SDK 原本只监听 `pointermove`，移动端轻触不能改变状态。现在同时监听 `pointerdown`，且验收已通过。
6. **程序化层抢夺真实主体**：首版透明瓶体偏离照片主体、内部圆柱过于厚重。最终版只把程序化层作为与真实瓶体对齐的低透明交互反馈，不再作为第二个主体。

## R21 补充：可运行结果不再被视觉超时吞掉

整体目标没有变化：用户输入一个想法，系统交付一个可打开、可交互、与目标相符的网页；案例研究、素材能力和 Three.js 都只是实现手段。

本轮用“明亮的城市公共饮水地图”验证新的风格方向。路由为 `editorial-field + semantic-responsive-interaction + DOM/Canvas`，不再误读“不要中央产品”为产品页，也没有强制调用外部素材。生成网页已通过桌面、移动端、站点选择与无横向溢出的浏览器机械验收；它仍是候选，不进入精选案例，直到视觉定稿通过。

状态边界现在明确为：

- `failed`：没有形成可运行网页；
- `review-required`：网页已生成并可立即打开，但自动视觉验收超时或尚未完成；
- `complete`：真实页面视觉验收通过，可作为最终结果和精选案例来源。

这解决了 V1/V2 主链路里最影响体感的问题：自动视觉模型超时不再把已经生成的网页隐藏成失败。当前明亮地图候选已完成一次有证据的确定性修订：桌面标题由 351px 收敛为 143px，移动端标题为 85px；桌面与移动端横向溢出均为 0，站点选择与证据更新保持有效。

随后视觉复核发现，旧运行包虽有平面、线条、河流和点位，却缺少可辨认的地图语法；底图、路线和标记还使用了相互独立的变换组，因此视觉上更像随机线稿。确定性地图修订 `dedicated-3aeb34a5aacf` 已将街区轮廓、主次道路、运河与公园、站点编码、当前位置和四条步行路线组织到同一坐标组，并让选中站点同步切换路线与 DOM 证据。浏览器复验结果为：桌面和移动端横向溢出均为 0，WebGL 正常，四个站点全部可选，控制台错误为 0。该运行包仍保持 `review-required`，不进入精选案例，直到最终视觉确认。

本次缺陷同时沉淀为生成约束：信息地图首屏必须无需说明即可识别为地图，并至少具备道路层级、街区或水系、站点身份、当前位置和选中路线；不得再用随机线条、抽象曲线、粒子或孤立点位冒充地图。

进一步视觉复核确认：上述“可识别地图语法”仍不足以支撑公共饮水点这类地点决策主题，因为虚构街区无法建立地点可信度。真实地理修订 `dedicated-c0514ddead80` 使用项目本地缓存、保留署名的 OpenStreetMap 徐汇滨江底图，把西岸美术馆、油罐艺术中心、龙美术馆与星美术馆的地理坐标投影到同一 Three.js 场景，并明确将水质、距离与开放状态标为产品演示数据。运行期不请求外部瓦片，也没有放宽现有 CSP；桌面、移动端、键盘操作、减少动态效果与本地素材加载均已通过机械复验，控制台错误为 0。该候选仍为 `review-required`，等待最终视觉确认后才能成为精选案例。

由此形成新的边界：地点决策型主题优先使用带授权与署名的真实地理底图；底图投影、地标、站点、路线与证据必须共享同一数据源。只有在无法取得合规底图时才允许程序化回退，而且必须明确标注为示意地图，不能把演示站点伪装成真实公共设施。

该结论没有继续扩张为送水调度系统，而是回归“想法生成优秀网页”的第一目标，沉淀为通用能力 `place-grounded-experience`。能力在 Codex 编码前把地域职责分为三类：地点影响查询与行动时使用“真实地域证据”；地点承载历史与空间连续性时使用“地域空间叙事”；地点只提供材料与情绪来源时使用“地域氛围转译”。没有地域职责的目标明确拒绝地图。工作台会显示被选中的策略，精简执行包同时携带数据真实性与创意自由度边界，使模型获得必要理解，而不是获得一个固定地图模板。

# V2 投影仪摆放助手端到端验证 R52

## 设计契约

- Entry mode: Brief-led validation
- Request revision: R52
- Target user and context: 正在比较家用投影方案的小户型租住者，需要在不理解投射比等专业概念的前提下判断摆放位置是否可行。
- Desired first impression: 明亮真实的同一间客厅中，投影仪、墙面画面和二者距离关系一眼可辨。
- Visual ambition: Functional + Immersive
- Experience architecture: Spatial Stage
- Scene base: Three.js/WebGL；语义 DOM 提供完整控制、读数、解释和保存行动。
- Scene persistence: 客厅、墙面和投影仪贯穿整个操作过程；只有移动端控制层可收合。
- Foreground control model: 距离、安装高度、水平偏角，以及白天/夜间环境模式；推荐结果和保存操作保持可见。
- State-to-scene mapping: 参数必须改变投影仪位置、投射锥体和墙面画面的尺寸/梯形/亮度；环境模式必须改变房间环境光和投影可读性。
- Mobile transformation: 控制面板变为紧凑抽屉或底部面板，场景仍可见。
- Fallback: WebGL 不可用时显示同一房间关系的语义俯视/立面示意、全部参数、估算说明和保存行动。
- Visual constraints: 暖白墙面、浅木家具、自然日光和少量影院蓝；不要暗色科技控制台、巨大标题、随机粒子、中央装饰球或固定三屏长滚动。
- Information constraints: 明确说明数值为演示估算；用户无需先理解投射比即可看懂“移动—变化—建议”。
- Operation constraints: 不自动循环、不用鼠标位置偷偷修改状态；所有主要输入具备触摸和键盘等价路径。
- State constraints: 控件值、场景几何、可读指标、推荐提示和保存结果来自同一状态。
- Environment constraints: 继续使用本地 `127.0.0.1:8143`、现有 Codex 生成管线和无模型机械审计；不调用 MiniMax，不要求外部素材。
- Primary journey: 看懂房间关系 → 调整距离/高度/偏角 → 看见画面与建议同步变化 → 切换白天/夜间 → 保存推荐摆放位置。
- User-defined phases: 锁定合同；检查路由；生成一个候选；机械与浏览器验收；按证据归档或记录失败。
- Required artifacts: 本记录、生成运行、编译报告、机械场景差异、桌面/移动端浏览器证据、最终归档决定。
- Autonomy authorization: 用户已确认并要求继续；允许项目内可逆实现与本地验证。
- User-decision boundary: 不远端发布；不进行开放式视觉精修；未通过双门禁的结果不进入精选案例库。

## 可观察完成标准

1. 普通用户在约 10 秒内能回答：这是投影仪摆放助手、可以调整哪些位置、调整后墙面画面会怎样。
2. 距离、安装高度或水平偏角至少一个操作同时产生明显场景变化和一致的可读指标变化。
3. “白天观影/夜间影院”作为高层操作，真实改变场景环境光与投影可读性，不能只切换按钮或文案。
4. 推荐提示来源于当前参数；演示估算清楚标注；保存操作有明确完成状态。
5. 桌面、390px 移动端、减少动态效果和 WebGL fallback 保留完整主要旅程。
6. 只有机械审计通过且独立视觉验收达到项目门槛时才归档为精选案例。

## 时间边界

- 只生成一个候选。
- 生成服务最多使用既有的一次编译重试；不启动独立开放式精修。
- 程序化场景即可证明业务，不等待外部图像或 3D 素材。
- 若候选未过门禁，记录失败原因并停止该案例，不进入无期限修补。

## 实际执行结果

- 任务：`job-3e5c5fa53299655e`；临时运行：`run-1gbv9fh`；模型：`gpt-5.6-sol`。
- 合同规划：27ms，正确选择 `product-atmosphere / interactive-field / procedural-field / dom-three-hybrid`；无需外部素材或 MiniMax。
- 第一次模型输出：约 125 秒返回；在结构门禁被拒绝，因为无外部素材的程序化候选仍声明了不合法 asset path。
- 第二次模型输出：约 116 秒返回；结构已通过，但 TypeScript 在 `scene.background` 的 `Color | Texture | null` 联合类型上直接调用 `.set()`，未通过编译。
- 总结：本轮耗时约 4 分钟，主要是两次 Codex 代码生成；合同规划、素材判断和本地测试均为毫秒至秒级。本机不是主要瓶颈。
- 决策：没有形成可运行页面，因此不进行机械场景差异、独立视觉验收或案例归档；不存在可向用户展示的合格结果。

## 本轮沉淀

- 新增可复用的“空间摆放 / 校准工作台”识别：主体、参数、可见结果与操作共同命中后，使用持续 `interactive-field`，而不是普通编辑页或固定三屏。
- 修正主体抽取：能够把“家用投影仪摆放助手”识别为产品主体，而不是把“小户型租住者”误当主视觉对象。
- 补充 Three.js 路由职责：设备位置、投射锥体、目标平面、梯形与环境光共享同一三维坐标，DOM 只承担控制与解释。
- 补充两个确定性生成约束：无获批素材时 `bundle.assets=[]`；动态背景色必须保存独立 `THREE.Color`，不得直接对 `scene.background` 调用 `.set()`。
- 验证：64 个测试文件、245 项测试全部通过；TypeScript 与 Vite 生产构建通过。构建仍有既存的无扩展名导入与大 chunk 警告，本轮未扩大处理范围。

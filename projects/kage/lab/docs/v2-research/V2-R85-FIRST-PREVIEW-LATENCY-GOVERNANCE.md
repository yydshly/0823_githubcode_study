# R85 · 首次预览与有界耗时治理

## 阶段目标

继续服务项目第一目标：用户输入一个想法后，尽快看到一个可运行的专属网页；后台视觉验收可以继续，但不能阻塞首次结果，也不能无限等待。

本阶段不制作新案例、不改变视觉风格，只修正生成主链的时间与反馈机制。

## 已确认的问题

- 编译成功时任务已经保存 `sourceReceipt.previewUrl`，通用工作台却只把最终 `bestReceipt` 当作可查看结果，导致页面已经存在但用户仍看不到入口。
- 阶段耗时仅由最近 40 条历史记录推算，长任务会丢失早期记录；阻塞期间的等待也可能被误算为模型或构建耗时。
- 总预算只在阶段入口换算为一次静态 timeout；MiniMax 请求、Codex/TypeScript 子进程和 Chromium 验收仍可能越过任务绝对截止时间。

## 本阶段实现

1. **立即预览**：工作台按 `bestPreviewUrl → bestReceipt → sourceReceipt` 选择当前可查看页面。首次编译成功后即可打开；只有 `complete + finalEligible` 才表示最终验收通过。
2. **权威阶段计时**：任务持久化 `planning / assets / authoring / reviewing` 四段累计耗时，只累计运行状态，阻塞和结束后的等待不计入。
3. **绝对截止时间**：runner 向下游传递同一 `GENERATION_JOB_DEADLINE_AT`。素材请求、Codex、TypeScript 编译和 Chromium 验收都按剩余预算缩短 timeout，并在预算耗尽时停止后续动作。
4. **兼容恢复**：旧任务没有累计字段时仍可由历史记录计算；新任务使用持久化计时，不依赖被裁剪的 history。

## 验收边界

- 编译成功但仍在视觉检查时，界面必须显示“已生成，可预览”，不得提前宣称最终完成。
- 阻塞 60 秒后恢复，60 秒不得计入任何生成阶段。
- 子步骤请求 30 秒、任务只剩 8 秒时，实际 timeout 不得超过 8 秒。
- 到达绝对截止时间后，不再启动新的素材请求、代码修复或浏览器验收。
- 本阶段不触发真实模型生成；以单元测试、类型检查、全量测试和生产构建作为证据。

## 后续阶段边界

R85 完成后再进入素材首轮质量治理：优先校验候选素材是否真实承担业务主体，必要时做有限并发或快速淘汰。该方向必须作为独立小阶段，不与本轮耗时治理混做，也不允许形成无限精修循环。

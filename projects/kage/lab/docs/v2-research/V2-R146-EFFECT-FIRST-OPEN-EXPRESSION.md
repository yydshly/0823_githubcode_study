# V2 R146 · 效果优先开放创作协议

## 阶段目标

把 V2 从“先选技术媒介，再形成页面方向”调整为“先选择最强体验效果，再反推实现手段”。本阶段只改造创作决策与作者输入，不新增案例、不接后台模型、不修改现有运行时，也不增加生成次数。

## 核心结论

- 3D、图片、声音、视频、蒙版、Shader、排版和动画都是表达手段，不是产品目标。
- 现有能力目录只提供可验证证据和启发，不构成创作白名单。
- Codex 在获取素材或编码前，内部比较三个真正不同的效果命题；差异必须来自视觉世界、时间关系、空间逻辑或用户角色，不能只换配色和页面皮肤。
- 比较阶段只选择一个方向进入执行，不代表三次构建，也不能触发额外素材批次。
- 用户硬要求、真实性、安全、性能和有界执行仍是有效边界。

## 新决策链

```text
用户想法
→ Experience Promise
→ 3 个开放效果命题（内部比较）
→ 选择 1 个最强且连贯的方向
→ 再决定素材、媒介、技术和交互
→ 1 次素材批次 + 1 次构建
→ 最终浏览器效果与证据
```

## 实现

- 新增 `src/v2/effect-first-expression.ts`：描述受众感知变化、开放探索、比较维度、方法自由和可观察效果证明。
- `CreativeDirectionSpec.effectFirst` 成为媒介规划之前的作者指令。
- `leadMedium` 与 `supportingMedia` 明确标记为资源规划锚点和可选支持，不再充当创意边界。
- `DirectCreativeAuthorPackage` 明确允许未进入项目目录的新技术、合成方式和交互语法。
- V2 页面把媒介显示改为“资源锚点 / 非技术白名单”，并说明三方向内比、一方向执行。

## 有界验收

- `npx tsc --noEmit`：通过。
- 目标协议测试：4 个文件、21 项测试通过。
- 新增测试覆盖：三方向内比、未列出手段可用、媒介非创意边界、硬约束仍保留、执行预算不扩张。

## 后续阶段

下一小阶段不是继续生成大量案例，而是修复视觉评审独立性：禁止案例归档脚本自行填写高分，把创意大胆程度、感知变化、惊喜但不困惑、手段必要性和整体统一性绑定到最终截图与 `runId + bundleHash`。完成后再用一个全新主题进行端到端验证。

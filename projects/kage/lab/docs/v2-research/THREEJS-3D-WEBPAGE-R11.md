# R11 · Threejs-3D-Webpage 案例研究

## 结论

这个案例值得接入的不是黑金视觉、机械花外形或固定三章节，而是一条可复用的实现能力：

> 当用户目标需要一个抽象主体发生组装、绽放、展开或结构揭示时，用程序化部件建立单一主体，把全局滚动拆成各部件的错峰局部进度，并让相机、材质、灯光、雾与后期共享同一叙事时间轴。

它补充了 Kage V2 的“程序化可动主体”路线，但不能替代真实产品 GLB、人物、建筑或品牌资产。

## 实现原理

1. 固定画布在 DOM 内容之后持续渲染，DOM 负责章节、导航、暂停和重置。
2. 外层花瓣、内层叶片、铰链、轨道和核心均由 BufferGeometry 与 Three.js 基础结构程序化生成，无外部 GLB。
3. 全局滚动进度经过相位偏移，变成每个部件不同的局部进度，产生逐层展开而不是整体机械旋转。
4. 同一进度同时改变相机路径、主体开合、核心高度、颜色、雾、曝光、灯光和 Bloom。
5. 指针只提供轻微观察偏移；主叙事仍由滚动决定。
6. 默认使用 WebGPURenderer 的 WebGLBackend；只有显式 `?backend=webgpu` 才尝试 WebGPU。

## 本地运行证据

- 桌面：1440 × 900，首屏、中段和终点均成功渲染一个 Canvas。
- 中段展开度约 `0.5259`，终点为 `1`，证明滚动确实驱动结构状态。
- 暂停按钮可切换为 `aria-pressed="true"`。
- 390 × 844 且 `prefers-reduced-motion: reduce` 时无横向溢出。
- 桌面与移动检查中无控制台错误和页面脚本错误。

## 进入生成器的规则

### 选择

- brief 明确要求单一抽象主体发生组装、绽放、展开、解构或结构揭示。
- 部件变化本身能解释材料、生长、机械关系或核心形成。
- 程序化造型可以诚实承担主体，而不是冒充现实商品。

### 构建

- 先定义部件拓扑和三个以上语义状态，再编写几何与动画。
- 全局时间线只负责故事推进；各部件通过局部进度产生错峰。
- 相机、材质、灯光和后期读取同一语义进度。
- DOM 保留正文、导航、行动和 WebGL 失败时的完整内容。

### 拒绝

- 真实商品、人物、建筑或需要精确品牌造型但没有可信资产。
- 结构变化不能解释主题，只能制造“很酷”的装饰。
- 2D 分层、视频或真实模型能更直接、更低成本表达同一关系。

## 发现的工程缺口

- 单文件约两千行，渲染、场景、输入和 UI 没有模块边界。
- 依赖 CDN 模块，缺少锁文件、离线构建和自动测试。
- 指针视差忽略触摸，没有等价的触摸观察操作。
- 高细分几何、粒子和 Bloom 在低端移动设备上仍需分级。

Kage 只吸收能力原理，并用现有契约、资产边界、移动降级、性能预算和浏览器验收补齐这些缺口。

## R12 · 已进入生成契约

- 能力 ID：`procedural-articulated-subject`
- 选择输入：抽象主体语义、结构变化语义、部件语义和体验模式。
- 构建输出：3–12 个有语义部件组、全局进度到错峰局部进度、DOM + Three.js 混合渲染。
- 执行约束：指针只作辅助观察；减少动态效果保留稳定语义状态；Bloom 可关闭；像素比上限 1.5。
- 新主题验证：“潮汐机械罗盘”命中能力；要求真实 GLB 精确还原的耳机目标拒绝该能力。

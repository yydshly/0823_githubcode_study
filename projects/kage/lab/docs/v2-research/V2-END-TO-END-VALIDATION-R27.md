# V2 R27：受约束想法到网页端到端验证

## 设计契约

- 入口：brief-led；用户已明确授权直接继续。
- 测试主题：社区公共图书馆“安静座位观察台”，此前案例与生成任务中未出现。
- 目标用户：希望选择安静座位的普通访客。
- 第一印象：日光、建筑平面图、纸质借阅卡；明亮、克制、可信。
- 视觉野心：Functional + Editorial。
- 体验架构：Editorial Flow；平面图可以由 Canvas/SVG/DOM 增强，但不能成为中央装饰性 3D 物体。
- 主要旅程：选择楼层与时段 → 采光、噪声、可用率、插座状态和平面图高亮同步变化 → 预约这个座位。
- 明确禁止：暗色全屏、中央 3D 物体、巨型标题、随机粒子、玻璃科技风、电影式长滚动。
- 数据边界：全部为演示数据，页面必须明确标注，不伪装成真实图书馆实时数据。
- 生成边界：一个候选；独立视觉验收失败时至多一次证据驱动精修；只有最终门禁通过才归档。
- 运行环境：`npm run dev -- --host 127.0.0.1 --port 8143`，规范 URL 为 `http://127.0.0.1:8143/workbench.html`。

## 本轮对项目的修复

1. V2 现在能识别“选择楼层和时段后，同步更新/高亮”这一类表单语义，不再只识别鼠标、拖动和点击措辞。
2. 明确要求平面图、示意图或图表时，导演路线改为 `dom-canvas-hybrid`；DOM 承担完整信息与回退，Canvas 只承担空间高亮。
3. 视觉门禁的 `semantic-probe` 不再只按一次 Tab，而是实际操作当前视口内的可见业务控件，并确认检查发生在中段进度。
4. 案例库仍保持 12 个入口；新精选案例进入后，将能力重叠的风扇诊断台从目录降级，但保留完整源码与直达页面，可随时恢复。

# V2 单任务端到端验证 R54

> R59 勘误：本轮把“不调用 MiniMax、不依赖外部素材”混入了创意 brief。它们是当时的实验调度条件，不是用户确认的产品限制，不应被后续实现继承。当前行为以 [R59 用户意图来源隔离](V2-INTENT-PROVENANCE-R59.md) 为准。

## 设计契约

- Entry mode: Brief-led validation
- Request revision: R54
- Target user and context: 陶艺学习者需要在网页中理解氧化铁、长石、灰釉比例与烧成温度如何改变同一只小茶杯，并形成一份可保存的釉方。
- Desired first impression: 明亮、自然、具有真实材料实验感；首屏直接看懂“正在调整一只茶杯的釉色”，不是常见暗色科技展厅。
- Visual ambition: Immersive
- Experience architecture: Spatial Stage；程序化 Three.js 茶杯主体持续可见，前景控制负责材料比例、烧成温度与保存釉方。
- Scene base: WebGL / Three.js，DOM 保留完整说明与操作。
- Scene persistence: 从未烧制器物、混合响应到烧成结果持续可见。
- Foreground control model: 少量高层参数和“保存这次釉方”主行动；输入后场景与结果说明同步变化。
- State-to-scene mapping: 初始陶坯 → 材料比例变化 → 温度改变光泽/细裂纹/流釉边界 → 保存釉方；异常时停止动画并保留可读说明。
- Mobile transformation: 控制面板转为紧凑底部区域，不遮挡玻璃主体和主行动。
- Fallback: WebGL 不可用或 reduced motion 时，DOM 仍解释参数、当前形态和结果。
- Visual constraints: 自然日光、暖灰工作台与矿物釉色；避免暗紫科技风、随机粒子、巨型标题和固定三屏模板。
- Information constraints: 约十秒内识别对象、操作、形态结果和保存行动；专业参数标明为模拟而非真实工业计算。
- Operation constraints: 沿用现有工作台、V2 合同、素材门禁、Codex 生成、候选保全和浏览器验收；不新增平台或 API。
- State constraints: Codex 完整生成最多一次，本地确定性修复最多两轮，现有视觉精修最多一次；任一边界耗尽立即停止。
- Environment constraints: `http://127.0.0.1:8143`；模型使用项目现有 Codex 配置。历史执行曾把“不调用 MiniMax、不依赖外部素材”误写在此处；R59 起它们只能作为独立实验条件记录，不能进入用户创意 brief。
- Primary journey: 调整配方与温度 → 同一茶杯表面发生可归因变化 → 看懂模拟结果 → 保存这次釉方。
- User-defined phases: 提交新想法；生成并恢复；真实浏览器验收；记录耗时与结论。
- Required artifacts: 持久化 Job、生成 bundle 或明确失败报告、候选恢复报告、桌面/390px 浏览器证据、R54 结论。
- Autonomy authorization: 用户已“确定”，授权执行一个受控端到端验证。
- User-decision boundary: 不重复创建任务；不为通过验收而无限精修；若资产门禁意外要求真实素材，记录为明确阻断而不是自动扩展范围。

## 可观察完成标准

1. 只创建一个全新 Job，记录每阶段耗时和最终状态。
2. 若 Codex 返回 bundle，原始候选先于校验落盘；本地修复不超过两轮。
3. 成功时生成页可打开，茶杯主体和业务闭环在桌面、390px 手机均可理解；失败时工作台给出明确阶段、错误类别和 artifact 路径。
4. 不调用 MiniMax，不发生第二次完整 Codex authoring，不无限等待。

## 停止边界

- Job 数量：1。
- 完整 Codex authoring：1 次。
- 本地确定性修复：最多 2 次。
- 视觉精修：沿用现有最多 1 次。
- 总任务：沿用项目硬超时；到终态即停止，不自动再生成变体。

## 实际执行

- Job：`job-a25c897814be550b`，只创建 1 个。
- 方向准备：约 70 秒；V2 结构合同本身在 11ms 内完成，主要时间消耗在受约束的创意理解。
- 唯一一次 Codex authoring：约 115 秒，模型为 `gpt-5.6-sol`。
- 首次门禁：候选已先保存，随后因 SDK 不导出 `GeneratedPointer` 而编译失败。
- 本地恢复：重放同一候选，修复为 `GeneratedFrame['pointer']`；没有再次调用模型，约 1.6 秒完成并通过编译。
- 生成结果：`dedicated-9535f6c5e73a`，4 个源码文件，0 个外部素材，约 16.9KB 源码，编译约 495ms。
- 自动视觉判断：达到 90 秒硬上限后停止，未发生第二次 authoring；Job 正确进入 `review-required`。
- MiniMax：0 次调用。

## 真实浏览器证据

- 桌面 1440×1000：页面可打开、无失败请求、无横向溢出；同一茶杯、四项参数、模拟解释和保存行动均可见。
- 语义交互：氧化铁从 3% 调至 12% 后，茶杯由象牙色变为赤褐色，文案从“温润象牙”改为“矿物赤褐”；保存后显示完整配方摘要。
- 移动端 390×844：无横向溢出，内容与行动均可到达；页面高度约 1515px。
- Reduced motion：完整参数、结果和行动仍保留。
- WebGL 关闭：页面明确显示“3D 增强没有启动”，标题、说明和保存行动仍可读；当前降级页没有保留滑杆和完整结果数据，属于可理解但不完整的回退。

## 质量结论

最终状态是 **L2 可检查原型，不能归档为精选案例**。

通过项：

- 想法被正确收敛为单一交互工作区，没有落回固定三屏或暗色科技模板。
- 参数确实改变同一对象和说明，不是装饰性鼠标动画。
- 业务闭环清晰：理解实验 → 调整参数 → 阅读模拟结果 → 保存釉方。
- 失败候选可保全并在不重跑模型的前提下恢复，R53 的有限恢复机制在真实任务中生效。

未通过精选标准的原因：

- 程序化茶杯轮廓和把手偏粗糙，仍有基础几何体感。
- 视觉上主要表现了色相变化，光泽、细裂纹和流釉边界没有形成足够可辨认的材料差异。
- 移动端主体被放大并裁切，虽然可操作，但观察完整器形的体验弱于桌面。
- WebGL 回退只保留了内容骨架，没有保留可操作参数和完整结果。
- 自动视觉模型超时，系统没有把未经判断的结果误标为完成或自动归档。

## 对项目的直接结论

R54 证明当前架构已经具备“一句话目标 → V2 约束 → 一次专属生成 → 候选保全 → 有限本地恢复 → 可运行网页 → 多状态验收”的闭环。当前主要缺口不再是能否生成，而是材料级视觉质量判断和低成本验收：自动视觉模型超时会把可运行结果停在待评审，程序化素材的质量级别也不能仅依据“无外部素材”自动判定。后续优化应围绕快速视觉评分、移动构图与语义材质差异展开，而不是继续增加生成轮次。

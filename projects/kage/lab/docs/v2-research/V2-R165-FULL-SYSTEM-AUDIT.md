# KAGE V2 R165 全系统审计

日期：2026-09-03

## 结论

KAGE 的方向可行，且已经拥有相当多真实能力：自然语言目标解析、参考案例研究、图像/3D/Canvas/Web Audio 等媒介、专属页面构建、浏览器证据、有限修复和案例展示都已存在。

当前核心缺口不是继续增加案例，也不是继续增加规则，而是把这些能力接成一条唯一、真实、可恢复的主链：

`idea → experience intent → relevant references → creative direction → assets → bounded build → browser evidence → independent experience judgment → archive`

现在项目仍由三套半连接系统组成：

1. V2 创意协议与研究系统；
2. V1/旧工作台生成服务器；
3. 人工 delivery、finalizer 与多个静态归档表。

因此，V2 页面上已经描述的先进协议，并不等于用户在工作台点击“生成”后会完整执行这些协议。这是近期出现结果不稳定、代码原生画面偏多、评价与用户感受不一致、归档状态混乱和反复等待的根因。

## 第一目标

用户描述一个想法后，KAGE 应在不过度询问、不无限探索的前提下，参考真正相关的优秀案例，选择适合主题的媒介与互动，产出具有明确产品价值、主题专属记忆点和目标感受的优秀网页。

3D、图像、声音、视频、排版、蒙版、Shader、Canvas、真实数据和程序化图形都只是可选手段。唯一不可放松的硬边界是：用户明确要求、真实性、运行与可用性、证据身份、安全和有界执行。

## 审计范围

- 产品入口：首页、兼容工作台、V2 创意入口、研究页、案例库、正式产品页。
- 创意链：brief、Creative Contract、参考证据、方向选择、媒介和结构决策、DirectCreativeRun。
- 执行链：模型 authoring、素材、编译、确定性修复、浏览器检查、视觉精修。
- 质量链：产品完整性、创意承诺、视觉评分、互动因果、移动端、证据身份。
- 归档与发布：generated run、case run、delivery、research reference、formal product、GitHub Pages。
- 运维与性能：超时、轮询、测试分层、服务身份、缓存和仓库可恢复性。
- 安全与素材：iframe 隔离、子进程环境、素材许可、隐私、API 边界。

本次没有逐页人工观看全部 98 个历史 generated run；采用关键入口实测、代表性正式产品实测、目录/注册表全量扫描和核心代码/测试静态审计。因而本报告可以判断系统结构与产品风险，但不能据此宣称每个历史案例的视觉质量。

## 当前能力与健康度

| 环节 | 健康度 | 当前事实 |
| --- | --- | --- |
| 1. 首页与入口 | 部分可用 | 首页视觉成立，但“从想法开始”入口藏在侧栏；公开路径没有清楚区分 V1 工作台、V2 直接创作和案例浏览。 |
| 2. 兼容工作台 | 可运行但属旧链 | 390px 无横向溢出，主 CTA 可见；实际仍进入旧 `generateCreativeRun → candidate → assets → dedicated bundle` 链。 |
| 3. V2 创意协议 | 协议较强、执行断裂 | 能形成意图、参考、方向、素材责任、有限执行和验收要求；但页面主要导出给 Codex 的包，没有统一执行器。 |
| 4. 参考研究 | 有价值但尚未成为首轮导演输入 | 已有 21 个正向证据包和六类能力研究；实际旧规划器首次选方向时仍看不到这些证据。 |
| 5. 构建与运行时 | 较强 | 专属 bundle、Three.js/Canvas/音频、编译修复、浏览器复核均存在；本次生产构建通过。 |
| 6. 用户感受与优秀判断 | 不可靠 | `creativePromise` 可省略且缺失时仍通过；视觉分数多由案例脚本自填，不能独立证明优秀。 |
| 7. 产品完整性 | 有基础但模板化 | 正式产品检查固定为 entry/use/result/continuation 四步，适合作为观察视角，不应成为所有网页结构。 |
| 8. 归档与案例库 | 多源分裂 | generated、case、delivery、research、formal-product 分别维护，容易漏登、串图和误标精选。 |
| 9. 有界执行 | 部分实现 | Job 路径已有次数和总时限，但直接接口仍可使用 420 秒模型超时；历史脚本可轮询 11–20 分钟。 |
| 10. 本地研究安全 | 尚可 | 路径、大小、部分 CSP 和解码检查已存在。 |
| 11. 远端/多人产品安全 | 未就绪 | iframe 同源隔离失效、模型子进程继承主机环境、API 无身份/配额、素材许可不闭合。 |
| 12. 发布与恢复 | 高风险 | 大量 V2 文件未跟踪；本地 HEAD 仍与旧远端相同；Pages 未部署 cases 与部分研究文档，线上存在 404。 |

## P0：停止继续堆案例，先关闭六个断点

### P0-1 建立可恢复基线

当前 KAGE lab 约有 67 个已修改文件和 1033 个未跟踪文件，V2 核心目录本身仍未被 Git 跟踪。远端不能代表当前研究成果。

动作：先生成精确纳入清单，隔离缓存、临时证据和其他项目改动，再建立 KAGE 专属可恢复提交。此步骤不改变产品行为。

### P0-2 建立唯一 Direct 创作编排器

新建版本化项目入口，不接工作台后台也可以先用 CLI/项目函数实现：

`brief → ExperienceIntent → 0–3 references → 1–3 internal directions → winner → asset freeze → DirectCreativeRun → existing build/review → archive`

必须复用现有构建和浏览器验收，不再以大量一次性 finalizer 作为主流程。

### P0-3 把用户感受变成必填体验承诺

新增版本化 `ExperienceIntent / ExperiencePromise`，至少回答：

- 用户应该感受到什么；
- 应该理解什么；
- 应该记住什么主题专属画面或动作；
- 最终要做什么；
- 选用媒介如何帮助这种感受。

当前 `creativePromise` 为可选，缺失还会通过；必须只对新协议强制，旧记录保持可读。

### P0-4 独立质量判断与统一归档结论

把单一 `pass` 拆为：

- `productReady`：能否作为产品使用；
- `experienceExcellent`：是否真正兑现体验承诺；
- `archiveDisposition`：`featured | research-only | rejected`。

最终判断必须绑定真实截图/媒体状态、可观察事实和独立判断，不能使用作者脚本写入的分数自证优秀。

### P0-5 统一 Artifact Registry 与证据身份

建立唯一注册表，按 tier 管理 generated、research、featured、formal-product。它应生成案例页面、V2 卡片、构建清单和 Pages 部署清单。

每个条目绑定：最终文件 SHA-256、素材清单和许可、截图/媒体哈希、viewport、交互状态、runId、协议版本、参考版本和停止原因。任何 bundle 改动自动使旧证据失效。

### P0-6 先修安全隔离再考虑远端生成

- iframe 恢复 opaque origin，只保留 `allow-scripts`，能力通过 `postMessage` 传递。
- Codex 子进程使用环境变量白名单，不继承 API key 和用户主机秘密；输出落盘前扫描秘密。
- 素材 `publishable/license/provenance` 不得在构建和归档间丢失。

在完成前，项目只适合作为本机单用户研究工具，不应开放远端多人生成 API。

## P1：使主链稳定、快速且不压制创意

1. 首轮创意导演直接接收 ExperienceIntent 和 0–3 个相关参考，停止由三套 baseline 固定候选决定方向。
2. 方向数按不确定性为 1–3 个；一个方向明显最好时直接继续，不强制凑三个和自评分。
3. 媒介默认“未决定”，图像、真实媒体、视频、音频、字体、3D、Shader、蒙版、程序图形和数据均为一等资源，不默认 `code-native`。
4. 风格距离只做诊断；不能改变胜出方向，也不要求为了不同而不同。
5. 产品路径改为语义状态图，检查进入、理解/使用、结果和下一步是否存在，但不强制恰好四段或固定页面数量。
6. 工作台只保留一个清楚主入口；V1 兼容能力移至“历史/实验”区，避免用户误以为旧预览就是 V2 生成结果。
7. 统一 180 秒总截止线：60–120 秒首稿后立即展示；只有有精选潜力的候选才进入一次视觉精修。
8. 测试分三层：编辑 smoke、当前候选自适应证据、提交/发布前全量门。历史 11–20 分钟脚本退出常规流程。

## P2：产品化补充

- 参考库用语义相关性与人工黄金集校准，合并重复的研究/正向证据库。
- 建立少量人工确认的黄金案例；用途是校准判断，不是提供模板。
- 增加键盘、对比度、减少动态、图片 alt、帧率、资源体积、音频静音和失败降级的中心门。
- 用户 brief 不再写入 URL；增加无留存模式、删除、保留期限和公开归档脱敏。
- 公共演示自托管字体；第三方模型调用前说明发送内容和供应商。
- 非图片媒体做真实解析与解码规模限制，不只检查文件头。
- 固定 Node 版本，添加服务 `/health` 返回项目根、commit、启动时间和 bundle 身份，防止连接旧端口。
- 内容寻址去重资产；首页用 WebP/AVIF 缩略图，原图只保留一份。
- README 从长历史日志改为“当前状态 + 架构 + 下一步”，历史迁入 changelog。

## 现场验证结果

- 本地关键路由 10/10 返回 HTTP 200：首页、工作台、案例库、V1、V2、研究页、核心原型、两项正式产品和一个精选案例。
- `npm run build` 通过；TypeScript 与 Vite 均成功。存在两个超过 500 kB 的入口 chunk 警告，应在 P2 做按路由拆分。
- 关键协议/质量/正式产品/截止线测试：6 个文件、39 项全部通过。测试通过说明当前实现符合当前规则，不代表规则已经能判断体验优秀。
- 1280px V2 首页出现水平溢出；390px 已消除溢出，但顶部六项导航触控目标约 27px 高，低于常用的 44px 触控建议。
- V2 移动端页面约 35,772px 高，案例库桌面约 27,295px 高。内容虽完整，但产品状态、研究记录和历史能力全部堆在同一页，认知负担过高。
- 正式产品“KAGE 创意导演”首屏有真实素材、明确价值和行动，证明项目能产出较强页面；问题是该质量尚不能由主链稳定复现。

## 性能事实

69 个任务中，10 complete、24 review-required、26 failed、9 blocked。有完整阶段计时的 19 个任务：

- authoring 中位约 75.6 秒；
- reviewing 平均约 37.4 秒；
- 活跃总耗时中位约 113 秒，P90 约 169 秒；
- 已有 7 次 90 秒和 6 次 120 秒模型超时。

因此长期等待主要不是电脑渲染慢，而是模型 authoring、重复视觉闭环、历史轮询脚本、不同超时入口和人工/任务闲置叠加。首稿模型的 60–120 秒无法完全消除，但 7 分钟直接接口、11–20 分钟轮询和每个中间候选都双重验收可以消除。

## 发布与数据风险

- GitHub Pages 当前没有复制 `cases.html` 和 `cases/runs`，V2 页面却链接这些路径，线上已存在 404。
- 研究文档也没有全部进入部署清单，README 会链接到不存在页面。
- 33 个 V2 delivery 中只有 11 个有 `asset-manifest.json`；部分案例有资产无 manifest，另有 manifest 无本地资产。
- 归档没有统一验证素材许可；模型生成和用户上传资产默认 `publishable:false`，但该信息会在后续构建上下文中丢失。
- 当前 98 个 generated run、25 个 case run、33 个 delivery、12 个 research reference 和 2 个 formal product 由不同真相源维护。

## 可行性与成熟度

- 单点研究与能力积累：约 70%–80%。
- 构建、运行时和浏览器证据：约 70%。
- 真实、可重复的“想法到优秀产品网页”主闭环：约 35%–45%。
- 本机单用户研究安全性：约 65%。
- 远端多人产品化：约 30%–40%。

这不是“目标无法实现”，而是需要停止横向堆案例，把已存在的能力纵向接通。若先完成 P0，后续案例才是在验证产品能力；否则继续制作案例主要是在验证当前操作者和大模型的临场能力。

## 下一阶段停止条件

阶段只完成以下四项，不新增普通案例：

1. 当前 V2 可恢复基线建立；
2. 唯一 Direct 创作编排器可以跑通一个新 brief；
3. ExperiencePromise、最终文件/截图哈希和三态归档成为新协议强制门；
4. 工作台/CLI 任一入口能在统一截止线内展示首个可运行结果，且失败诚实停止。

只有四项完成后，才使用一个新主题做阶段验证，并只归档一个最终结果。

# V2 R28：程序化关节主体受约束生成验证

## 设计契约

- 入口模式：brief-led；用户已授权按整体目标直接推进。
- 第一目标：验证用户给出一个新想法后，V2 能否先选择已验证能力与主题视觉锚点，再由 Codex 在有限边界内生成一个优秀、可运行、可归档的网页。
- 测试主题：潮汐机械罗盘；此前没有作为最终案例生成。
- 目标访客：希望理解今晚潮汐窗口的沿海观察者与普通访客。
- 第一印象：白昼海事仪器、盐雾蚀刻、克制而可信；不是黑金机械花或通用科技装置。
- 视觉野心：Immersive。
- 体验架构：Spatial Stage；固定 Three.js 主体持续可见，DOM 承担标题、状态说明与最终行动。
- 视觉锚点：不对应真实商品的潮汐机械罗盘，由外环、潮汐翼片、中央浮标核心、刻度骨架组成。
- 状态映射：闭合校准 → 低潮/涨潮结构展开 → 满潮稳定构图；部件、相机、材质、灯光与海面反光读取同一语义进度。
- 操作边界：滚动驱动主变化；指针只提供轻微观察；触摸与减少动态效果保留稳定关键状态。
- 降级：WebGL 不可用时保留罗盘最终剪影、三个潮汐状态说明和“查看今晚潮汐窗口”。
- 禁止：黑金、紫色科技、随机粒子、通用网格、真实商品冒充、电影式长章节、复制 IRIS 花瓣外形。
- 生成边界：Codex 5.6-sol；一个候选；不调用 MiniMax；最多一次证据驱动局部精修；不做自由生成对照。
- 运行环境：`npm run dev -- --host 127.0.0.1 --port 8143`。
- 时间边界：首个可运行页面目标 5 分钟；自动验收 90 秒；一次修订最多 3 分钟；完整任务最多 10 分钟，超时返回当前最佳结果与明确原因。

## 验证 Brief

> 为一座沿海潮汐观测所设计一枚“潮汐机械罗盘”的沉浸式网页。主视觉是一个不对应真实商品的抽象机械装置，由外环、潮汐翼片、中央浮标核心和刻度骨架组成。滚动时部件从闭合校准逐层展开，指向低潮、涨潮和满潮三个状态；相机、材质、海面反光和灯光共同响应同一进度。最后行动是“查看今晚潮汐窗口”。画面像白昼海事仪器与盐雾蚀刻图，明亮、克制、可信，不要黑金、紫色科技、随机粒子、真实产品冒充或电影式长篇章节。

## 停止规则

- 只执行现有生成链路，不在本轮增加新研究能力。
- 若任务进入 `blocked`、`failed` 或超过总预算，停止并记录阻断，不启动第二个候选。
- 只有真实浏览器视觉锚点、结构变化、移动端和回退均通过，才允许进入案例库。

## 结论

- 本轮没有生成页面，也没有归档；它验证出了能力路由的系统性缺口，而不是视觉质量问题。
- 原因：原 brief 的最后一条禁止项包含“真实产品冒充”。旧路由直接扫描整段 brief，把禁止项误判为用户要求真实产品，于是关节主体选择从应有的程序化路线退化为生成素材路线。
- 修复：能力与参考选择只读取去除禁止片段后的正向 brief；完整禁止项继续保留在 `intent.negativeConstraints` 和 Codex 执行包中。
- 回归证据：同一 brief 现在必须选择 `procedural-articulated-subject`、`dom-three-hybrid` 和程序化视觉锚点；相关 17 项测试及生产构建通过。
- 下一次运行是修复后的正式验收，不是本任务的第二候选；仍只允许一个页面和一次有证据的局部修订。

## 对 V2 的直接结论

1. 已证明“想法 → 能力选择 → Codex 独立源码 → 可运行 Three.js 页面 → 自适应浏览器检查”可以在一个新主题上贯通。
2. 主要耗时不是合同、参考研究或素材门，而是 Codex 完整结构化源码生成（约 73%）以及超时的自动视觉精修（约 19%）。
3. 当前最大产品缺口不是继续增加案例，而是把作者调用拆成可控的“结构骨架 + 视觉增量”，并让阶段状态在编码结束、截图开始时立即更新。
4. 工作台摘要此前遗漏 `procedural-articulated-subject`；现已补齐，并有回归测试覆盖。
5. 下一轮不再生成新主题；先降低单次 bundle 延迟并提高视觉锚点的主体抽取准确性，再做一次可归档验收。

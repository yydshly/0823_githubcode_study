# V2 R83：有界场景构成路由

## 服务目标

本能力只服务第一目标：把用户想法生成成与主题匹配、可运行且可验收的网页。它不替代创意合同、状态素材策略、Codex authoring 或浏览器验收，而是在素材生成前补充一个问题：当前目标能否由单张主素材完成，还是必须拆成 2.5D 图层或真实 3D 空间。

## 三条路线

| 路线 | 触发条件 | 素材边界 | 失败处理 |
| --- | --- | --- | --- |
| `single-image-hybrid` | 普通产品、编辑信息、DOM 工具或未要求空间拆分 | 保留原合同素材；允许单张高质量主素材与克制增强 | 非阻断，使用原回退 |
| `layered-2d` | 明确前中后景、景深、视差、穿越/推进，或树冠/云层/水面等环境主体随输入改变 | 独立环境、主体、前景、深度/状态场；同一素材不可重复充当多层 | authoring 前阻断并给出具体素材请求 |
| `spatial-3d` | 真实 GLB、环绕检查、拆解或部件空间关系 | 可检查模型及状态证据 | 缺少模型时阻断，不伪造 3D |

## 边界

- 不修改 V1、已归档案例和已有预览 bundle。
- 旧 V2 合同缺少该字段时默认 `single-image-hybrid`，不新增阻断。
- 程序化 Three.js 工作区默认保持现有能力；不会为了使用图片分层而覆盖灯光、材质或几何状态。
- 普通 `layered-depth` 风格名称本身不会触发 2.5D；必须存在可验证的空间或环境状态语义。
- 一次只选择一条路线；不同时堆叠单图、2.5D 与真实 3D。

## 执行链

`用户 brief → V2 创意合同 → 场景构成路由 → 素材职责/质量门禁 → 一次 Codex authoring → 有界浏览器验收 → 最优结果归档`

工作台显示场景构成路线；Codex 执行包携带同一决定。`layered-2d` 会生成四项独立职责，质量门禁禁止一张图片被重复登记为环境、主体、前景和深度。

## 停止规则

本轮只完成路由、职责、门禁、工作台可见性和回归测试，不启动新主题生成，不对树冠案例继续做开放式精修。下一次真实生成只选择一个未使用主题，验证路由是否减少“一张背景图冒充完整空间”的问题。

## 首次有界验证

新主题“清晨屋顶温室”要求穿过结露玻璃、前景水滴、中景藤蔓、远景城市视差，以及湿度驱动的叶片凝露变化。确定性合同得到：

- `continuous-scroll / continuous-canvas`
- `dom-canvas-hybrid`
- `layered-2d / required`
- 四项独立职责：`scene-environment`、`scene-subject`、`scene-foreground`、`scene-depth-field`
- 空素材时在 authoring 前暂停，并说明同一张背景图不能重复充当四层

回归同时证明：已经成立的 Canvas 材质路线和 Three.js 环境因果路线不会被新层降级或重写。该主题尚未调用素材模型或 Codex authoring，因此不是案例库候选。

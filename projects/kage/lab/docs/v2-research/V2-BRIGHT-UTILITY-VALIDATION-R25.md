# V2 R25 · 明亮实用工具风格验证

## 目标

验证 V2 能否把一个新想法稳定路由为明亮、实用、可操作的网页，而不是再次落入暗色电影化、中央海报或长滚动叙事。

## 设计合同

- 入口：brief-led，用户已授权继续推进与生成。
- 用户：带着老式台式电风扇来到社区维修工作坊的普通访客。
- 第一印象：日光下的工业说明书、彩色装配图和社区公告。
- 体验野心：Functional + Editorial。
- 页面架构：Editorial Flow；DOM 承担信息与操作，Canvas/SVG 只承担程序化剖面和部件反馈。
- 主路径：选择故障 → 部件、检查顺序、安全提示、难度同步变化 → 查看三个工作阶段 → 预约维修桌。
- 素材边界：不对应商业型号，不依赖真实商品图；程序化示意优先，素材缺失不得阻塞主体流程。
- 禁止项：暗色全屏、中央产品海报、巨型标题、电影式长滚动、随机粒子、玻璃科技界面。

## 实施范围

只完成一个可运行切片，不扩展后台预约系统：

1. V2 合同与风格路由校验。
2. Codex 生成一个专属页面。
3. 验证故障选择、阶段浏览、行动反馈。
4. 验证桌面、移动端、键盘和降级表现。
5. 仅在效果与交互通过后归档为案例。

## 结果与问题沉淀

- 风格差异成立：本案例使用日光说明书、彩色装配图和工具型状态选择，不复用暗色全屏、中央素材和粒子长页。
- 素材阶段为 `procedural`，没有等待 MiniMax，也没有调用外部图片生成。
- 首次结构评审虽为 100 分，但截图揭示 Canvas 被不透明根背景完全遮住；这说明仅统计 Canvas 数量不足以证明主体可见。
- 修复方法：网格背景移到 `body`，内容根保持透明；随后调整桌面主体尺度与移动端独立取景。
- 自动第二次模型精修超过 90 秒，因此按“有限深度”原则停止模型重试，使用确定性代码调整完成收尾。
- 最终稳定入口：`/cases/dedicated-5694e0a3a022/`。

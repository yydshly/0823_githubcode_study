# R86 · 素材质量早检与有界恢复

## 阶段目标

继续服务“把用户想法生成优秀网页”的第一目标：错误素材必须在 Codex 编码前停止，不能等待低能力适配器生成后再发现它必然不合格，也不能让一个未经审核的上传文件凭来源标签越级通过。

本阶段不新增素材平台、不制作案例、不调用真实模型，只收紧现有 MiniMax、项目素材、上传素材与 Codex 构建之间的质量边界。

## 已修正问题

1. **上传质量不再丢失**：上传文件注册为 `L2-inspectable` 后，恢复任务时继续保留该等级；L2 不能因 `user-provided` 来源被隐式提升为 L3。
2. **停止注定失败的 MiniMax 调用**：当前图片适配器最高只声明 L2。必需且阻断式的 L3/L4 职责直接生成具体 Codex / 真实来源请求，不再先等待 MiniMax。
3. **只把通过素材交给 Codex**：首次生成路径与恢复路径一致；`assetGate.acceptedAssetIds` 之外的低质或无关素材不进入 authoring bundle。
4. **素材服务失败变成可恢复门禁**：图片服务异常或空结果不再把整个任务打回泛化 failed/planning，而是保存方向、合同、素材请求和 `resumeBuild`，停止自动重试。
5. **保留已有网页**：新任务生成或素材早检失败时，已有 iframe、打开链接和交互不被等待/失败占位层覆盖。
6. **有界候选数**：单轮图片适配器最多处理两个候选，与既有“只生成最高收益两项”的策略一致。

## 验收语义

- `L2-inspectable` 表示可检查候选，不代表可发布或可承担 L3/L4 主体。
- `chatgpt-generated` 与 `licensed` 的旧项目素材仍可按已有精选来源兼容；未经明确等级的用户上传不获得同等信任。
- 素材门禁失败为终态 `blocked`，同一 Job 只等待明确补充；不会自动重新解释目标、重新调用素材模型或开始 Codex 编码。
- 工作台明确显示“已接受 X 项 / 未通过 Y 项 / 不会自动重试”。

## 本阶段不解决

- 图片像素级内容理解、主体是否正确、真实 Alpha、棋盘格假透明、截断 JPEG/PNG 与主体占比检查。
- ChatGPT ImageGen 的产品内 API 接入。
- 模型对素材进行多轮自评或自动无限重画。

上述第一项是下一阶段的候选，但必须保持确定性、低成本和一次早检边界；不能再次把生成链扩展成无上限视觉探索。

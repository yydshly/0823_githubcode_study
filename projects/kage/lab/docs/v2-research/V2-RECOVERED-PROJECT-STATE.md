日期：2026-08-27

## 不变的产品目标

用户说出一个期望的想法，系统理解对象、受众、情绪、变化和行动，参考经过研究的优秀网页能力，按需生成或组织素材，并构建一个新的、具有创意且可运行的网页体验。

V2 不是案例复制器，也不是固定模板选择器。它要解决 V1 把宏观想法直接交给模型后出现的三个问题：

1. 模型自由范围过大，需要重复理解、选型和试错；
2. 素材、构图、交互与技术路线缺少有证据的中间决策；
3. 耗时长，视觉质量、解释能力和停止条件不稳定。

```text
优秀来源与本地案例
  -> 证据分级与实现原理
  -> 可组合视觉机制
  -> 适用条件、禁区与验收
  -> brief 的视觉决策
  -> 有边界但仍有创意的 Codex 构建
```

## 已恢复的用户方向

- MotionSites 只是第一个参考来源，后续还应研究其他优秀案例库和本地实验。
- 重点是理解为什么效果好、如何实现、依赖什么素材与交互，而不是收集缩略图。
- 案例必须沉淀成原理、机制和约束，再供模型选择、组合和创新。
- 不复制案例的固定颜色、字体、区块数量或品牌外壳。
- 以最终效果为目标；DOM、媒体、Canvas、Shader 和 Three.js 只按需要选择。
- 一次只验证一个最小闭环，避免宏观任务造成长时间无结果。
- V1 保持独立归档和演示；V2 复用稳定底层，但有独立入口和研究链路。

## 当前已经具备什么

给定 brief，V2 已能输出可检查的创意契约：意图、参考证据、核心视觉职责、最多三个兼容机制、交互含义、最小充分渲染器、素材责任、回退、拒绝机制和验收状态，并形成一份自包含的 Codex 构建输入。

## 尚未完成

2. 除 `scroll-scrub-media` 外，产品空间揭示、交互即信息、身份/品牌叙事等路线仍缺少完整 E4 运行证据。
3. V2 Composer 尚未直接调度 Codex 执行契约、回传页面、限时评审和局部修订。
4. 缺少统一的研究队列，无法清楚看到候选案例为何被晋级、保留或排除。
5. 当前本地 V2 变更尚未统一归档与提交。

## 下一阶段：R08 代表性覆盖，而非继续堆案例

R08 建立三个明显不同的研究队列：

1. **真实空间对象**：什么时候真实 GLB、相机和灯光不可替代；
2. **交互即信息**：指针、触摸或选择行为什么时候真正承担发现与比较；
3. **身份与证明**：品牌构图、证据内容和素材安全区如何共同建立可信度。

每个队列遵守同一晋级链：

```text
公开或本地来源
  -> source evidence
  -> 一个最小运行原型
  -> opening / middle / ending / mobile / reduced-motion 证据
  -> 有边界的能力合同
  -> 决策层选择器
```

同一时间只实现一个原型。没有足够素材、运行证据或移动回退时保持候选状态，不让模型静默用占位几何或通用科技风代替。

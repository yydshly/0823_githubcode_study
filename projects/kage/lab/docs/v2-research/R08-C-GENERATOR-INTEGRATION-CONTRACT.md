# R08-C · 生成契约接入

状态：已实现并总结归档；取消自由生成对照  
更新时间：2026-08-27

## 目标

让 R08-B 已验证的“交互即信息”能力参与 V2 的想法解析，而不是继续制作视觉样例。输出必须能直接告诉 Codex：何时使用、为什么使用、输入改变什么、如何降级；不适用时也必须明确拒绝。

## 实现边界

- 复用现有 V2CreativeContract、表现能力选择和体验导演，不新建生成系统。
- “连续媒体滚动”负责主表现路线；“交互即信息”是正交决策，两者不被强制设为二选一。
- 只接入一个 E4 能力，不新增参考案例、素材、模型供应商或独立生成页面。
- Three.js 仍是可选增强；语义 DOM 始终承担可读证据、操作和回退。

## 决策结果

- 适用：brief 明确要求比较、证据、年代、关系、选择或探索；同时存在信息职责和有语义的主要输入。
- 拒绝：静态展示、无需交互、真实 GLB 拆解、自由旋转或其他未被当前原型证明的路线。
- 选中输出：E4 能力 ID、命中信号、理由、scroll/pointer/touch/keyboard 输入、四类信息结果、减少动态效果和无 WebGL 降级。
- 未选中输出：拒绝理由和仍可查看的 E4 运行证据，不为页面强加装饰性交互。

## 优化后能力总结

- 能力：semantic-responsive-interaction，证据等级 E4。
- 解决的问题：阻止模型用装饰性跟随动画替代真正的信息交互。
- 选择依据：比较、证据、年代、关系、路径、选择或探索，同时存在信息职责和有语义的主要输入。
- 拒绝依据：纯静态展示、无需交互、GLB 拆解、自由旋转，或交互不能改变用户理解。
- 输入与结果：scroll、pointer、touch、keyboard 必须改变同一组选择状态、证据数值、叙事层和视觉形态。
- 技术边界：语义 DOM 是完整基础；SVG/Canvas/Three.js 只按职责增强，并保留减少动态效果和无 WebGL 路径。
- 生成器接入：完整决策已进入 technical.semanticInteraction，Codex 得到明确的使用与禁止条件。

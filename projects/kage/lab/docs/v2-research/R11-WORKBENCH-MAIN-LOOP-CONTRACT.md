# R11 · 工作台主生成闭环契约

## 目标

V2 研究只服务一个产品结果：用户输入一句想法，工作台在已有服务器任务链路中交付一个高质量、可运行、可访问的专属网页。参考案例、能力原型、Three.js 和素材生成都不是独立产品。

## 本轮只解决的缺口

V1 的服务器任务已经能完成解释、素材、Codex 构建、浏览器验收和最终结果恢复；缺口是 Codex 仍接收宽泛 brief，没有收到 V2 已沉淀的参考证据、能力选择、体验节拍、素材职责和停止条件。

本轮把 `V2CreativeContract` 接入这条既有主链，并在工作台显示模型实际采用的约束摘要。不增加模型、不增加素材渠道、不增加候选数量。

## 主路径

1. 用户输入想法并点击“生成并构建最佳网页”。
2. 浏览器即时显示本地 V2 约束摘要：参考方向、已选能力、实现路线和执行边界。
3. 服务器以相同 brief 生成完整 V2 Creative Contract，并将摘要写入持久任务。
4. 现有解释与素材流程继续运行；完整契约随构建请求交给 Codex 5.6-sol。
5. Codex 只构建一个候选；现有浏览器验收最多进行一次局部修复。
6. 工作台恢复并展示唯一最佳结果 URL；失败时保留当前页面和可读错误。

## 状态与反馈

- `idle`：等待有效想法。
- `contract-ready`：本地约束已确定，用户可在模型启动前看见选择。
- `generating`：服务器任务运行，并使用任务返回的约束摘要校准页面。
- `complete`：唯一最佳网页已经进入主预览。
- `failed`：显示失败阶段，不清空已有结果。

## 体验边界

- Desktop：1440px，摘要不压缩主预览，不制造第二个工作台。
- Mobile：390px，摘要单列，无横向滚动。
- Keyboard：生成按钮、摘要与最终链接保持可达。
- Reduced motion：不依赖动画解释任务状态。
- 失败回退：V2 约束生成是确定性本地操作；远程失败时仍显示约束和原结果。

## 性能边界

- 本地契约选择应在一次同步交互内完成，目标低于 50ms。
- 每次任务只允许一个作者候选、一个素材批次、最多一次自动视觉修复。
- 本轮验证禁止触发真实 Codex 或 MiniMax；用单元测试和浏览器 API mock 证明请求内容与界面状态。

## 完成证据

- 单元测试证明服务器构建请求收到完整 V2 Creative Contract。
- 持久任务保存可恢复的 V2 约束摘要。
- Prompt 明确按照能力选择分配 DOM、媒体与 Three.js 职责，而非强制套用 WebGL 效果。
- 浏览器测试覆盖桌面、移动端、键盘和远程失败回退。
- 工作台能直接显示本次生成采用的参考方向、能力与路线。

## 不在本轮范围

- 新增参考站点或能力原型。
- 真实 GLB 生产、MiniMax 质量研究或 Figma 流程。
- 多候选对比、开放式自我探索或无限精修。
- 重新设计 V1 工作台或案例库。

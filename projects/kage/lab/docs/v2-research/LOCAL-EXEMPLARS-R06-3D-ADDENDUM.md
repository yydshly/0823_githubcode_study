# R06 3D 补充核验

## IGLOO 电影式拆解

`3d (1).html` 是本地目录里目前证据最完整的 Three.js 叙事案例。页面提供五个可寻址场景：完整冰屋、块体断裂、冻结企鹅、量子吉祥物和 DNA 螺旋。浏览器运行中五个按钮都产生不同的 Canvas 画面状态，且无页面错误。

它值得沉淀的不是全息科技风，而是“可寻址镜头状态”结构：复杂 WebGL 体验被拆成可进入、可测试、可复位的状态，滚动再负责在状态之间连续插值。这一结构可以进入 V2 的 Three.js 叙事能力；遥测面板、实验室文案和蓝色全息外观不应成为默认视觉模板。

## AERO-X 产品拆解舱

`aero_x_premium_3d_interactive_showcase (2).html` 的 CLOSE、OPEN、FLOAT、EXPLODE 和 WAVE 状态都能产生不同画面，说明产品拆箱、悬浮和爆炸视图链路确实存在。不过，自动演示触发 Web Audio `setValueAtTime` 参数错误，运行日志连续报错。

因此它暂时保持 `hold`：可复用的是产品状态机和 360 度观察结构，不可直接晋级的是当前声音实现和过重的实验室界面。

## 其他 3D 页面

- `3d.html`：8,192 粒子、多形态转换和 4,500px 长滚动，适合研究粒子形态叙事，但仍是技术展示语法。
- `3d (2).html`：单屏能力实验台，提供块体拆解、粒子形态和 Web Audio 控制，适合隔离验证。
- `3d (3).html`：四阶段主线时间轴，适合验证“资产状态与叙事阶段”关联。

## 晋级规则

Three.js 案例进入正式生成能力前必须同时满足：

1. 三维状态变化能够解释对象，而非只制造科技感。
2. 每个关键镜头可直接寻址、复位和自动测试。
3. DOM 文案在关闭 WebGL 或低性能设备上仍能完成基本信息传递。
4. 声音、输入设备和 reduced-motion 都有独立降级策略。

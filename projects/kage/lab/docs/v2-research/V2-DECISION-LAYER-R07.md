# V2 视觉决策层 R07

## 解决的问题

V1/V2 初始链路已经能把 brief 转换为体验模式、素材职责、参考证据和验收条件，但“参考案例为什么适合当前目标”与“最终应该使用哪种视觉机制”之间仍有空白。Codex 因而需要再次自行探索构图、输入方式和渲染技术，造成时间增长与结果波动。

R07 在创意契约中加入 `direction`，把研究结论转换成编码前可检查的导演决策：

```text
brief
  → experience pattern
  → primary visual role
  → 1–3 visual mechanisms
  → interaction meaning
  → minimum sufficient renderer
  → fallback and rejected mechanisms
  → Codex authoring prompt
```

## 决策对象

### 核心视觉职责

- `environment`：环境本身承担主要空间和情绪。
- `subject`：独立产品、服装、材料或艺术对象承担主要识别。
- `information`：档案、数据或并列证据承担主要理解。
- `spatial-object`：真实 3D 模型和空间结构承担主要解释。
- `procedural-field`：没有外部素材时，由可验证的程序化状态承担变化。

### 可组合机制

当前机制来自 R06 本地运行证据：环境窗口、状态故事板、主体标本场、品牌蒙版、滚动堆叠档案、指针揭示、产品微电影和电影式 3D 拆解。系统选择一至三个机制，并为每项记录职责、原因、证据等级和来源案例。

机制不是页面模板。它只描述“什么应该产生效果”和“为什么”，页面章节数、构图、字体、色彩和具体镜头仍由当前目标决定。

### 交互含义

默认以滚动推进叙事，指针只做次要空间反馈。只有 brief 明确提出发现、检查、选择、悬停或自由旋转时，指针或直接导航才成为主输入，并同时生成触摸与键盘替代策略。

### 技术选择

- `dom-only`：内容与离散状态已足够。
- `dom-media-hybrid`：连续图片或视频承担环境和状态变化。
- `dom-canvas-hybrid`：局部材质、蒙版、像素或程序化场由 Canvas/Shader 承担。
- `dom-three-hybrid`：只有真实模型、可检查深度、相机或结构状态确实必要时使用 Three.js。

DOM 始终保留可阅读内容、导航和最终行动。增强层失败时必须按契约回退，不能让页面失去产品意义。

## 已验证的代表路由

| Brief 类型 | 核心视觉 | 机制组合 | 技术路线 |
| --- | --- | --- | --- |
| 梦境中的同一房间逐渐清晰 | 环境 | 环境窗口 + 状态故事板 | DOM + 连续媒体 |
| 透明薄纱逐渐形成服装 | 独立主体 | 主体标本场 + 状态故事板 + 产品微电影 | DOM + Canvas/Shader |
| 真实 GLB 声学设备拆解 | 空间对象 | 电影式 3D 拆解 + 主体标本场 + 状态故事板 | DOM + Three.js |
| 海洋记忆档案与可选探索路径 | 环境 + 证据 | 环境窗口 + 状态故事板 + 滚动堆叠档案 | DOM + 连续媒体；直接导航为主输入 |

## 防止过度约束

- 一次最多选择三个机制。
- 品牌蒙版只在数据、成果、统计、字形、标志或蒙版被明确提出时选择。
- 指针揭示只在输入本身承担发现或检查意义时进入候选。
- 没有真实模型时，明确拒绝电影式 3D 拆解。
- 展陈、档案和空间关系优先于“记忆”这一泛情绪词，避免海洋记忆展陈被误判成梦境页面。
- 被拒绝的机制写入契约，Codex 不得在生成阶段自行恢复。

## 工作台操作

在 `/pages/v2/` 输入目标并点击“生成 V2 创意契约”。新增的 `DESIGN DIRECTION` 区域展示：核心视觉职责、渲染路线、机制组合、交互含义、技术理由和回退方式。点击“复制 Codex 构建输入”后，完整 `direction` 会与原有体验节点、素材职责、参考证据和验收条件一起进入构建提示。

## 验证

- 44 个测试文件、139 项测试通过。
- 常规生产构建通过。
- GitHub Pages 独立 V2 构建通过。
- 浏览器核验梦境、时装、GLB 和海洋展陈四类路由，无页面错误。
- 390px 触屏视口无横向溢出，复制操作可用，决策卡在移动端单列显示。

构建仍报告项目既有的 Vite 扩展名前瞻警告、Three.js 大块提示和若干 Pages 运行时素材路径警告；本轮没有扩大这些问题。

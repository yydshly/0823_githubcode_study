# 本地优秀案例研究 R06

## 研究结论

这批本地页面证明，优秀效果的核心并不是默认使用 Three.js，而是先建立清晰的视觉对象、叙事动作和素材构图，再选择成本最低且最匹配的渲染方式。用户指定的三个页面全部以视频和 DOM 排版为主；它们之所以有效，是因为素材承担了环境、主体或产品变化，页面代码负责控制观看顺序和信息层级。

本轮共扫描 `Downloads` 中 52 个 HTML 文件，并重点核验用户指定的三个页面、同批次六个候选和若干较早的 3D/产品实验。研究结果分为展示范例、局部组件、技术实验台和排除项，避免将“可运行”“视觉好看”“可复用能力”混为一谈。

## 用户指定的三个案例

### 1. Plety：素材驱动的完整产品故事板

`gemini-code-1785085812851.html` 是三者中页面结构最完整的一个。它使用一个全屏视频建立情绪，随后用三组交替双栏视频解释功能，并在末段再次用大幅媒体收束。主要机制是视频、固定导航、IntersectionObserver 渐入和响应式 DOM，而不是 Three.js。

值得沉淀的是“媒体节拍决定章节”的方法：先定义观看顺序，再分配文案和页面高度。限制是四个外部视频都没有 poster、离线与 reduced-motion 回退，当前属于视觉范例，不是完整交付范例。

### 2. Airlines：把素材当作进入环境的窗口

`gemini-code-1785086266144.html` 用舷窗外的飞行影像铺满视口，只留下一个标题、一个行动和克制导航。它的价值不在复杂技术，而在判断正确：素材本身就是空间入口，因此页面不再追加多余图形。

可复用原则是“环境型素材使用全屏窗口，文字服从素材安全区”。它不能单独证明完整页面能力，因为只有一个首屏状态。

### 3. Sports AI：主体安全区与媒体标本场

`gemini-code-1785086534757.html` 没有把视频强行铺满，而是把方形动态主体放在大面积浅色留白中，标题和按钮依附主体安全区。它说明：如果素材是独立对象而非环境，就应使用标本场式构图。

这对素材生成尤其重要。模型不应只生成“好看的对象”，还要同时提供主体位置、文字留白、裁切边界和移动端替代构图。

## 目录中发现的其他有效案例

### 应晋级为研究范例

- `gemini-code-1785146858646.html`：Harvest Stats。将视频裁入品牌字母形蒙版，并与统计数字、衬线标题共同构图，适合“能力证明”章节。
- `gemini-code-1785213262826.html`：Fabrica Vanilla。用 sticky 卡片和长滚动轨道构成作品档案，适合并列对象浏览；四张外部图片在本地运行时有效。

### 有价值但暂缓晋级

- `gemini-code-1785146968079.html`：Nike Spotlight。鼠标/触摸驱动的聚光和揭示与“发现产品”含义一致，是优秀的“交互即信息”案例；但关键视频地址出现 ORB 拦截，且缺少无指针与低动效替代路径。
- `aether_gesture_product_demo.html`：Aether 产品微电影。适合在完整页面开发前验证一个英雄镜头和重播状态，仍需补充响应式与完整流程证据。
- `3d (3).html`：极地 3D 实验室。适合作为材质、相机、程序化对象和阶段时间线的技术验证台，不应直接成为生成网页的视觉模板。
- `code_artifact (1).html`：沙盘编年史。证明 Three.js 场景可以与复杂控制 UI 协同，但产品工具属性强于情绪型网页表达。
- `aero_x_premium_3d_interactive_showcase (2).html`：AERO-X 入口和视觉基调有潜力，需完成进入场景后的状态验证再决定是否晋级。

### 应排除

- `gemini-code-1785213206711.html`：Fabrica React 在运行时读取未定义的 `motion`，页面为空。
- `strategic_ai_landing_page.html`：与 Sports AI 是同方向的早期低完成度重复版本。
- `gemini-code-1784716627552.html`：MCP 2099 使用常见暗色、巨大标题和青色 3D 物体，但对象与产品含义关系弱，属于通用科技风。

## 沉淀出的七类视觉机制

1. **环境窗口**：全屏媒体让用户直接进入地点或情绪。
2. **主体标本场**：独立主体居中，版式围绕安全区组织。
3. **媒体故事板**：用多个媒体状态推动完整页面，而非重复同一个 Hero。
4. **品牌蒙版**：文字、标志或轮廓成为媒体容器，动态素材进入品牌语法。
5. **滚动堆叠**：并列对象通过 sticky 层级形成前后关系。
6. **指针揭示**：输入行为承担发现、比较或聚焦含义。
7. **产品微电影**：用一个短而可重播的镜头验证产品英雄时刻。

这些机制不是七个固定模板。后续模型应根据对象、受众、情绪和期望变化，选择一至三个机制组合，并明确为什么选、哪些机制不适用。

## 对 Kage V2 的直接补充

V1 的主要问题是把“想法”直接交给模型自由开发，缺少对素材角色、观看顺序、交互含义和交付边界的中间约束。R06 增加四项必选判断：

1. 核心视觉是环境、独立主体、数据证明，还是一组并列对象？
2. 用户应经历哪些状态变化，滚动或指针是否真的表达这些变化？
3. 素材需要什么安全区、比例、裁切和移动端替代？
4. DOM、视频、Canvas 和 Three.js 中，哪一种是完成目标的最小充分技术？

这会缩小模型的无效探索范围，但不会把创意固化成几种页面。约束的是决策质量和交付底线，不是最终构图。

## 推荐的创意组合

- 环境窗口 + 媒体故事板：目的地、空间、情绪与文化产品。
- 主体标本场 + 指针揭示：服装、材质、设备与艺术对象。
- 品牌蒙版 + 数据证明：成果、可信度与能力章节。
- 滚动堆叠 + 产品微电影：系列产品、作品档案和发布页面。
- DOM 编辑排版 + 局部 Three.js 深度场：需要真实空间感，但不值得把整页交给 WebGL 的场景。

## 交付边界

本轮没有复制这些 HTML 或外部素材进入项目。它们是研究证据，不是可直接发布的依赖。后续只有在素材许可、加载策略、poster、失败回退、reduced-motion、触摸和移动端构图均明确后，某项机制才进入生成器的正式能力目录。

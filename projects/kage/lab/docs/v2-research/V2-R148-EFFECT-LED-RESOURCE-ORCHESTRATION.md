# V2 R148 · 效果导向的开放资源编排

## 目标

R148 让 Codex 在选定体验命题之后，可以按最终效果需要选择和组合：

- 已有产品能力，例如真实地图、媒体、数据、模型查看器或领域服务；
- 固定 revision、许可明确且机制适用的 GitHub 实现；
- 大模型生成的图片、声音、视频、环境、材质或连续状态；
- Kage 已验证的运行时、交互、媒体、素材和降级能力；
- 为当前主题直接编写的原创代码与视觉合成。

这些来源不是技术清单或配额。没有任何来源是强制项，也没有模型、供应商或渲染技术白名单。最终浏览器体验仍是唯一质量判断。

## 与 R146 / R147 的关系

- R146 先比较三个效果命题，只实现一个最佳方向。
- R147 研究优秀产品与源码，区分完整体验、聚焦实验和机制基础设施。
- R148 在效果确定后，把经过审阅的能力、素材和原创实现编排成最少充分组合。

因此执行顺序是：

```text
用户目标
  -> 三个不同效果命题
  -> 选择一个最佳体验
  -> 列出视觉 / 时间 / 空间 / 声音 / 数据 / 交互职责
  -> 从开放资源中选择最少充分组合
  -> 一批素材 + 一次构建
  -> 真实浏览器质量门
```

## 资源边界

### 已有产品能力

只在目标相关、访问和许可明确、数据真实、运行稳定并有不可用回退时采用。不得把演示数据、生成地图或第三方产品能力写成真实业务结果。

### GitHub 实现

只借机制，不复制视觉身份。必须固定 revision，核对代码与资产许可、关键源码位置、现有运行时兼容性、移动端和失败回退。机制可用不等于最终视觉优秀。

### 模型生成素材

不限制模型供应商，以最终像素、声音或视频质量为准。所有生成属于唯一一次素材批次；结果必须实际查看或试听，并承担声明的视觉或产品职责。关键主体不能以低质量占位资产冒充最终结果。

### 项目能力与原创代码

已有能力只有在强化当前主题时才复用，历史案例不构成模板。允许为当前体验创造新的交互语法、视觉合成和状态结构，但仍受一次构建、确定性修复、移动端、减少动态和最终身份门限制。

## 防止无限探索

- 优先使用 R147 及项目已有的审阅证据，再考虑新的外部搜索。
- GitHub 依赖在完整构建前冻结；构建后只允许确定性修复，不静默轮换库。
- 模型生成只允许一个批次，不因质量焦虑反复换模型或重生素材。
- 资源数量没有固定上限或下限，但必须是完成体验职责所需的最少充分组合。
- 任一资源没有明确职责、证据或回退时不加入。

## 实现

- `src/v2/effect-resource-orchestration.ts`：开放资源类型、选择策略、质量门和执行边界。
- `src/v2/creative-direction-spec.ts`：把资源编排放在效果命题之后、媒介执行之前。
- `src/v2/direct-creative-author-package.ts`：把紧凑资源规则交给一次性 Codex 作者包。
- `tests/v2-effect-resource-orchestration.test.ts`：验证开放来源、无白名单、用户硬约束和有界执行。

## 阶段验证结论

R149“日食邮局”已完成全新 brief 验证：Codex 先确定沉浸式日食与明信片显影职责，再选择一张生成环境图加原创 Canvas/CSS/DOM 因果，没有强制接入 GitHub、3D、声音或第二批素材。最终桌面、390px、滚轮、拖动、键盘、保存及双回退均通过，独立视觉质量与 WowGate 均为 94，并以最终 `runId + bundleHash` 进入 V3 精选库。

同时复验 R135“棱镜种子剧场”（生成素材型）与 R143“冰箱今晚”（代码原生型），4 个测试文件、12 项断言全部通过，证明开放资源协议没有把已有媒介路线改成新的单一模板。

本阶段停止增加案例。下一阶段应把 R149 的资源职责、单批次素材和最终证据作为产品回归夹具，继续改善创意选择质量，而不是继续堆资源类别。

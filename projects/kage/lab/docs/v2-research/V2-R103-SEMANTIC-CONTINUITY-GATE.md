# V2 R103 — 主体连续性、证据强度与终态闭环

## 目标

把 R102 暴露的视觉缺口写进现有 V2 生成合同与审核链，使下一个候选在调用 Codex 之前就知道：主操作改变什么、什么必须保持不变、结果如何在主体上显现、终态必须同时保留哪些内容。

## 有界范围

- 不新增模型、素材供应商、渲染框架或第二工作台。
- 基于现有 `creative-contract → execution brief → generated bundle → visual review` 链路扩展。
- 先完成合同与审核规则测试；规则通过前不生成新页面。
- 规则通过后只生成一个全新主题候选，不再回修 R102 植物页面。

## 三项能力

1. **主体连续性**：合同区分 primary causal action 与 secondary selector。主操作前后 visual anchor 必须保持同一业务主体；换物种、换产品或换场景不能冒充“观察变化”。
2. **主体内证据**：合同要求至少一种可截图识别的视觉证据，如局部放大、结构揭示、材质变化、路径或标注；文案更新只能解释，不能替代视觉结果。
3. **终态闭环**：桌面 final 与移动端关键路径都要同时证明 visual anchor、primary result、primary action，而不仅检查节点存在于文档中。

## 实现顺序

1. 扩展创意合同与 execution brief，明确 `preserve / change / evidence / closure` 四类约束。
2. 为 direct-state 页面补充终态主体与结果可见性证据，避免只验证 DOM 存在。
3. 增加定向单测，覆盖“切换主体冒充变化”“仅文案反馈”“终态主体消失”三类失败。
4. 通过现有 build 与浏览器门后，再创建一个未使用主题的唯一验证候选。

## 完成标准

- 合同测试能够在模型调用前拒绝三类已知失败。
- 机械审核不重复或矛盾判定同一因果链。
- 新候选机械门通过，独立视觉验收达到可归档等级；未达到则记录结论并停止，不进入无限修复。

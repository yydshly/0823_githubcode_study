# V2 素材主导权验证 R60

## 第一目标

用户只负责描述想法和确实需要的限制；系统以最终网页质量为准，自由选择项目素材、模型生成素材、DOM、Canvas 或 Three.js。任何实现手段都不能为了“用上技术”而压过更好的最终效果。

本轮只验证一个新主题：古建筑榫卯互动学习。实验条件与用户意图分开记录，只创建一个候选，到可查看或明确失败即停止，不进行无限自动修复。

## 通过项

1. 原始想法、系统偏好和实验条件保持隔离，任务没有再伪造“用户禁止外部素材”。
2. 素材门禁在缺少主题资产时先阻断，接入真实项目素材后恢复同一 Job，没有重新创建任务。
3. 项目素材目录现在可以接收并识别 ChatGPT 生成资产，不再假装它是用户上传素材。
4. 页面可运行、无浏览器异常，四个阶段和最终行动均可阅读。
5. 独立视觉判断没有把“能运行”误判为“可交付”，正确拒绝了低质量结果。

## 未通过项

高质量木构件素材已经足以承担主题，但生成代码又用大型棕色基础几何体重建榫卯主体。这个几何体遮挡并压低了真实素材，导致：

- 真实木材和榫卯关系退化为背景；
- 对齐、咬合和受力变化不能从画面直接确认；
- 首屏与 CTA 收束被占位感几何体争夺焦点；
- 手机构图进一步裁切主体；
- 最终体验评分为 81 / revise，因此不能进入案例库。

这说明问题不只是“有没有素材”，还包括谁拥有最终画面的视觉主导权。模型不能因为页面允许 Three.js，就用较差的程序化对象覆盖已经更好的 L3/L4 素材。

## 已加入的系统约束

1. `dom-media-hybrid` 等媒体主导路线中，Three.js 只负责景深、遮罩、色彩、证据标注和轻量空间响应。
2. 当获批素材已经清楚表现主体时，禁止用 `BoxGeometry`、`CylinderGeometry`、`SphereGeometry`、`TorusGeometry` 或 `LatheGeometry` 重建并遮挡主体。
3. 程序化层达不到素材质量时，宁可使用媒体与 DOM，也不为了填满 `scene.ts` 制造低质量 3D 主角。
4. 交付摘要先判断视觉和产品体验，不再把“素材已达到 L3 但画面失败”错误描述为素材不足。
5. 项目目录资产可以通过 ID 提交到被素材门禁暂停的同一任务，并保留真实来源与质量等级。

## 结论与停止边界

本轮没有产出新的精选案例，但完成了更重要的质量闭环：系统第一次在“素材好、代码能运行、最终构图差”的情况下明确拒绝归档，并把失败转化为后续 authoring 的通用约束。到此停止，不手工美化本候选，也不继续调用模型重写。

下一次新想法或同主题重试时直接使用新规则；验收重点是高质量素材是否始终为视觉主角，以及交互是否让业务变化可见，而不是检查 Three.js 是否被强行使用。

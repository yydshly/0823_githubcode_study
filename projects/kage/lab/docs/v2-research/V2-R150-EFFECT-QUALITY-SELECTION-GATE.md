# V2 R150 · 效果质量选择门

> R154 兼容修订：用户明确模板相似不是失败，只要效果最佳即可。`template-inertia` 现保留为复核提示，不再单独淘汰候选；其他主题、因果、素材、行动和真实性拒绝信号保持有效。见 [R154 效果优先于模板差异](V2-R154-EFFECT-OVER-TEMPLATE-POLICY.md)。

## 设计契约

- Entry mode：revision-led；延续 R146–R149，不重做现有项目。
- Request revision：R150 / 1。
- Target user and context：在 V2 工作台描述想法、希望 Codex 直接生成优秀创意网页的用户。
- Desired first impression：用户能看见系统先按体验目标比较创意，而不是先套技术、模板或素材来源。
- Visual ambition：Functional；本轮改造的是创意决策可读性，不制作新的沉浸案例。
- Experience architecture：Editorial Flow；在现有创意契约中增加一块紧凑的效果选择门说明。
- Visual constraints：沿用现有 V2 页面语言，不新增工作台侧栏、卡片墙或装饰动效。
- Information constraints：明确区分“候选相对比较”和“最终浏览器质量证据”；技术数量、3D、声音、视频或素材来源不能获得额外分数。
- Operation constraints：用户每次生成 V3 契约时同步更新选择门；无需新增一次确认。
- State constraints：三个方向 → 拒绝不可用方向 → 只选择一个 → 再进入资源选择；全部不合格时必须在素材前停止。
- Environment constraints：现有桌面与 390px 工作台可读；现有 V1、V2.5、V3 归档链兼容。
- Primary journey：输入想法 → 生成契约 → 看见以目标为准的比较轴与停止边界 → 复制给 Codex。
- User-defined phases：一个小阶段；不生成新案例，不接后台，不增加供应商。
- Required artifacts：选择门 schema/派生器、创意方向集成、作者包指令、工作台可见说明、单元测试、浏览器证据、阶段结论。
- Autonomy authorization：用户已明确“始终以目标为准，继续”，允许完成可逆项目内改造，无需重复确认。
- User-decision boundary：不改变第一目标、不提交远端、不部署、不重做旧案例。
- Observable completion criteria：选择门位于资源决策之前；固定比较三个真正不同方向；评价围绕主题记忆、感官影响、惊喜清晰度、运行时意义、工艺潜力和行动收束；技术数量不计分；存在硬拒绝信号；全部失败时素材前停止；作者包、页面、测试与浏览器证据一致。

## 停止条件

- 不生成新的视觉案例或素材。
- 不把自评分数当成最终质量证据。
- 不修改既有归档证据，不让旧案例重新验收。
- 只修复本轮可复现的类型、测试、布局或浏览器阻断问题。

## 阶段结论

- `effectQualitySelection` 现在位于 `resourceOrchestration` 之前；模型必须先比较体验，再选择资源与代码。
- 三个候选必须在体验形态、标志性现象和运行时因果上不同；比较轴围绕主题记忆、感官影响、惊喜清晰度、运行时意义、工艺潜力和行动收束。
- 技术数量、媒介名望和来源名望不计分；3D、声音、视频和生成素材不会因“更高级”自动胜出。
- 主题可互换、静态等价、装饰性运行时、素材错位、模板惯性、行动脱节和真实性风险会直接淘汰候选；全部淘汰时素材前停止。
- 相对选择回执不冒充最终质量证据；最终结果仍需真实浏览器、自适应质量门与最终身份绑定。
- 完整六维选择门只保存在执行记录与 V2 页面；Codex 作者包携带三条紧凑执行规则。代表性旗舰作者包为 19,383 bytes，避免把决策改造变成新的上下文与耗时负担。

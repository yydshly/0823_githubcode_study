# V2 质量优先主体路由 R58

## 问题

任务 `job-a25c897814be550b` 要求展示一只可调釉色的小茶杯，但测试 brief 额外写入了“不依赖外部素材，以程序化 Three.js 表达”。旧契约又把陶瓷关键词自动路由为 `procedural only`，于是作者模型只能用旋转体、圆柱和圆环拼接主体。页面能够编译和交互，不代表茶杯形体达到成品质量。

该任务的真实结论已经是 `review-required / prototype-only`：素材达到 `L2-inspectable`，目标为 `L3-presentable`，没有进入案例库。问题不是应该继续无限精修，而是生成前的手段选择错误、生成后的实体辨识验收不够明确。

## 修正规则

1. 模型生成素材、项目已有素材和程序化 Three.js 都是候选手段，不预先禁止某一种；最终选择由主体辨识度、融合质量、交互因果和来源约束决定。
2. 釉色实验仍由 Three.js 承担可交互材质变化，但同时允许生成或复用一张器物参考素材，校正形体、比例、杯口厚度、把手连接、足部和真实受光；素材可用时也可承担融合主体。
3. 参考素材是可选增强：MiniMax 可生成 L2 候选；没有图片适配器时不阻塞程序化原型，但原型仍必须通过 L3 视觉门才能成为最终结果。
4. 茶杯、器物、设备、家具等可辨认实体若出现圆柱、蛋形、球体或圆环拼接痕迹，视觉验收必须标记 `placeholder-dominant / major`，`productIntent` 不得高于 65。
5. 仍只生成一个主候选，最多一次有证据的视觉精修；超时或基础形体不足即停止并保留待评审结果，不无限修复。

## 当前结果

- 旧茶杯页面保留为问题证据，不归档为精选案例。
- 新契约的视觉锚点为 `hybrid`：程序化材质主体 + 可选模型/项目器物参考。
- 作者提示与独立视觉验收均加入实体形体门禁。
- 没有图片生成器且缺少的仅是可选参考时，任务继续生成有边界的程序化候选；必需主体素材缺失时仍会阻断。

## 验证与停止

- `6` 个相关测试文件、`48` 个测试通过。
- TypeScript 与 Vite 生产构建通过；仅保留项目既有扩展名和 bundle 体积警告。
- 本轮不重新调用模型、不重做旧 bundle、不把失败案例加入案例库。下一次新 brief 才使用修正后的质量优先路由。

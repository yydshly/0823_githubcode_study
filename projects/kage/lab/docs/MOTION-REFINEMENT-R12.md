# R12：电影化指针与滚动运动精修

## 设计契约

- 入口模式：repair-led，基于用户在真实工作台中的可见反馈修复。
- 目标用户：用自然语言生成并审阅创意 Three.js 网页的人。
- 第一印象：场景会回应用户，但镜头稳定、克制、具有导演意图。
- 视觉野心：Immersive；体验架构为 Hybrid Workspace，工作台提供控制，iframe 承担实时空间证明，完整页面承担连续叙事。
- 保留：三种现有创意方向、生成资产、DOM 内容、质量档、减弱动效和无 WebGL 回退。
- 主要旅程：移动指针观察细微视差 → 滚动推进章节内镜头 → 平滑跨章 → 指针离开后回到稳定构图。
- 授权：用户已要求继续修复效果；范围内可逆的运动与测试修改直接实施。
- 完成标准：指针无突跳并可回中；滚动不直接驱动相机；每章内部轨道被实际采样；工作台滚轮可跨 iframe 驱动预览；桌面、390px、减弱动效和回退不回归。

## 根因与架构决策

1. 原指针信号被相机、场景组和 Shader 以不同节奏直接消费，形成漂浮感。现在由 `CinematicPointerController` 产生统一、帧率无关的位移、速度和活动度。
2. 原相机直接使用原始滚动段，且多节点路径只连接“上一章结尾 → 下一章开头”，章节内部关键帧没有完整播放。现在 `CinematicScrollDriver` 先播放章节轨道，再使用章节尾部窗口完成跨章过渡。
3. 相机采用局部 right/up 轴上的轻量视差与四元数阻尼；指针不再直接大幅平移世界。
4. 嵌入预览不再是静态 iframe。子页面把滚轮意图发给工作台，工作台推进自身滚动并把归一化分镜进度送回子页面。
5. 潮汐档案片原先逐帧累加位置和旋转，会随运行时间漂移。现在每帧从保存的静止姿态计算绝对偏移。

## 边界

- 本轮解决运动系统质量，不重新设计生成素材或页面信息架构。
- 静态截图只能验证构图；运动品质由真实浏览器中的时间序列状态、滚轮路径与回中行为共同验证。
- 生产 bundle 仍约 649 kB，Vite 的 500 kB 提示继续存在；它不是本轮新引入的运行错误，后续应通过场景插件动态导入拆包。

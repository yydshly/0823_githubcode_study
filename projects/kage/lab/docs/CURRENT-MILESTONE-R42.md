# 当前里程碑：从“能做出”到“稳定做出”

## 已沉淀的最终案例

案例目录当前只公开五个互补的模型构建结果，并保留两个项目能力基准：

1. `dedicated-ba4e9d10caaa-depth-field`：先锋时装，素材透明度、无边界融合与 2.5D 景深。
2. `dedicated-r36-delivery-final`：生物材料温室，三阶段资产转化与空间叙事。
3. `dedicated-896cfb7e6657`：云上观测站，连续环境素材与电影化空间路径。
4. `dedicated-1edb98865f4c`：智能声音产品，产品发布逻辑、滚动叙事与移动端精修。
5. `dedicated-8574ee46ab16`：梦境记录，同一真实房间的连续状态与最终行动收束。

前三个 `featured` 或后续达到双门禁的结果作为精选案例；其余 `refined` 作为备用精修案例。每个 brief 只允许一个当前最佳版本。

## 真实可靠性基线

截至 2026-08-26，本地持久化任务共 13 个：

- 自动完整完成：1；
- 失败：10；
- 阻塞：2；
- 运行中：0；
- 中位耗时：约 7.8 分钟；
- 最长耗时：约 25.6 分钟。

这说明项目已经证明“能够通过模型、素材、Three.js 和人工/增量精修做出好页面”，但尚未证明“一次点击能稳定得到好页面”。下一里程碑只解决后者。

## 下一里程碑的唯一目标

把工作台变成可恢复、有时间上限、最多一次精修的服务端任务：

`brief -> plan -> assets -> build -> browser check -> refine once -> best result`

工作台只负责创建任务和显示状态。页面关闭或刷新不能中断任务，也不能触发重复模型调用。

## 必须完成的四项工程

1. **服务端编排**：一个任务由服务端连续推进全部阶段；JSON 任务记录从“状态日志”升级为可恢复的执行依据。
2. **总时间预算**：单任务最多 12 分钟；规划 90 秒、素材 120 秒、首次构建 240 秒、机械检查 60 秒、一次视觉精修 180 秒、最终验收 30 秒。阶段超时立即保留当前最好结果并报告原因。
3. **失败隔离**：素材失败、TypeScript 失败、浏览器启动失败、截图失败和视觉不通过分别记录；截图失败不能把可运行页面判成失败。
4. **固定回归**：产品、时装、真实空间、文化展陈、抽象情绪五类 brief 每次只跑一轮；通过率、耗时、素材可见率和最终分数进入同一报告。

## 阶段结束条件

- 五个基准 brief 都生成可打开的独立页面；
- 至少四个首次构建通过机械检查；
- 最多一次精修后五个全部通过机械检查；
- 至少三个达到人工视觉“可展示”；
- 端到端均不超过 12 分钟；
- 案例库保持 4–6 个，新增结果必须替换重复或较弱案例。

达到这些条件后再评估 GLB 自动建模、音频响应、MP4 导出或更多模型接入。在此之前，MiniMax 仍只是可选素材源，Codex 是主解释、主构建和主精修能力。

## 已建立的门禁

`tests/case-catalog-integrity.test.ts` 检查：

- 案例数量保持在 4–6 个；
- brief 不重复；
- 只公开 `featured/refined`；
- 每个案例都有稳定归档的 `bundle.json` 与 `build-report.json`；
- 当前五个方向没有被错误替换或遗漏。

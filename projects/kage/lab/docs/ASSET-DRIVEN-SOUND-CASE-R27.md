# R27：声音产品素材驱动生成闭环

## 目标与输入

真实 brief：为一款面向独立创作者的智能声音产品，设计清冷、克制但有未来感的发布网页；先建立情绪，再解释核心能力，最后留下明确行动。

本轮不是模板换参，而是验证完整链路：目标描述 → 按需素材 → Codex 独立 bundle → 严格编译 → 四状态截图 → 视觉精修 → 只归档终版。

## 按需生成素材

项目原素材目录只有时装主体。声音产品 brief 没有合适素材，纯程序化路线容易退化为抽象几何占位符，因此使用内置 ImageGen 生成一张独立产品主体。

- 用途：Three.js 沉浸式产品发布页透明 hero subject。
- 主体：原创冷银声学设备，包含共振核心、透明声学膜和精密控制结构。
- 约束：单一完整产品、无文字、无 Logo、无场景画框、真实透明 Alpha、避免普通圆柱音箱或简单球体。
- 文件：`public/creative-assets/acoustic-resonance-instrument-v1.png`。
- 证据：1024×1536，Format32bppArgb，四角 Alpha 均为 0，2,143,595 bytes。
- 登记：来源为 `chatgpt-generated`，角色为 `transparent acoustic product hero`。

素材由 brief 标签自动匹配，未硬编码到页面模板，也没有误用时装素材。

## 第一次真实构建与失败吸收

第一次 Codex 5.6-sol 调用实际使用 1 个获批素材，但两次输出都被严格 TypeScript 门禁拒绝。

失败证据：模型使用了不存在的 `GeneratedViewport.pixelRatio`。SDK 的真实字段只有 `width`、`height`、`dpr`。

系统没有放过错误 bundle，也没有手工修改模型成品；生成提示补充了 GeneratedViewport、GeneratedFrame 和 GeneratedMountContext 的精确字段契约。

## 四状态视觉评审

机械门禁对 opening、middle、final、390px mobile 给出 100 / pass：均 ready、Canvas=1、无横向溢出、无 DOM 碰撞、滚动时间线完整。

截图与代码联合判断仍发现视觉缺陷：

- 桌面端透明乐器主体被始终可见的程序化圆柱大面积遮挡。
- quality=low 移动端完全没有加载获批素材，只剩裁切圆柱。
- 首屏视觉锚点与最终英雄画面因此弱于素材本身。

这证明“结构 100 分”只代表页面没有坏，不能替代视觉完成度判断。

## 视觉精修终版

Codex 5.6-sol 只针对截图证据生成隔离修订版：

- 终版：`dedicated-5dfdc4d0650e`
- 素材在所有质量档加载。
- 加载成功后隐藏程序化备用主体。
- 备用主体缩减为加载失败时的轻量共振晶核。
- 修正窄屏产品缩放、位移与滚动终点英雄构图。
- 保留共振环和信号线作为深度背景。
- 精修耗时约 225s，编译 496ms。
- 最终四状态再次达到 100 / pass，无浏览器错误。

视觉抽查确认：首屏为左文案/右产品；中段产品退入共振环与结构说明；终点产品重新居中并形成明确 CTA；移动端文案完整，产品从右下进入且没有矩形素材边界。

## 案例收敛

只归档终版 `dedicated-5dfdc4d0650e`，未归档有圆柱遮挡的中间版，并从生成目录删除中间运行。

案例总览现在保持为：

- 2 个能力基准。

- 智能声音产品素材驱动模型精修终版。

## 架构结论

当前核心链路已经形成真实证据：

```text
自然语言目标
  -> 检查素材缺口
  -> 按需生成透明主体并登记来源
  -> Codex 生成独立 DOM + Three.js bundle
  -> Schema / 路径 / 素材 / TypeScript 硬门禁
  -> opening / middle / final / mobile 浏览器证据
  -> 视觉模型只修有证据的问题
  -> 再编译、再截图、只归档终版
```

后续重点不应继续增加模板，而应换不同类型的真实 brief，验证素材策略、空间隐喻和滚动事件能否产生真正不同的成品。

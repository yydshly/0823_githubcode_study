# Model asset production pipeline

## Design contract

- Entry mode: revision-led implementation.
- Request revision: R8 — replace one-off demo assets with a repeatable model-materialization path.
- Target user: a creator who can describe an intended web experience but should not need to choose a Three.js demo or primitive.
- Desired first impression: the workbench exposes creative direction, production readiness and a real preview without pretending that an unavailable model capability exists.
- Visual ambition: Editorial workbench + Immersive result.
- Experience architecture: Hybrid Workspace. Selection, provenance, status and review remain semantic DOM; the selected result opens as a persistent Three.js stage.
- Primary journey: describe idea → inspect effect directions → select a direction → materialize required visual assets → inspect production report → open the generated Three.js preview.
- Autonomy authorization: the user repeatedly authorized direct continuation and implementation.
- User-decision boundary: real MiniMax generation requires a user-provided `MINIMAX_API_KEY`; publication still requires a human quality/license decision.

## Capability boundary

```text
Codex / MiniMax-M3
  -> interpret the brief
  -> emit bounded EffectSpec directions

MiniMax image-01
  -> execute image / texture / sprite requirements
  -> return image bytes
  -> materialize immutable local cache entries

AssetPlan + ProductionPlan
  -> retain L0-L5 quality, provenance, budget and publication state
  -> never promote generated output directly to publishable

Manifest compiler
  -> attach an inspected candidate to the flagship image-depth scene contract
  -> allow color-only staging when no aligned depth asset exists

ExperienceRuntime
  -> render the result with Three.js
  -> preserve semantic DOM and non-WebGL fallback
```

The language provider and the media adapter are recorded independently. For example, a direction may be interpreted by `codex-language-adapter` while its image requirement is executed by `minimax-image-01`.

## Quality and safety gates

- Generation is an explicit button action; opening the workbench does not spend media API quota.
- API keys remain in the Vite server process and are never returned to the browser.
- The image prompt is derived from the selected EffectSpec and capped at 1,500 characters.
- MiniMax output is requested as base64 and materialized locally because remote output URLs are temporary.
- JPEG/PNG signature, byte budget, stable cache identity and browser addressability are checked before integration.
- A fresh model asset starts at `L2-inspectable`, `publishable=false`; it may drive an inspection preview but cannot satisfy an `L3+` publication requirement until reviewed or upgraded.
- Missing image capability disables the production action and explains the exact environment reason; it does not silently replace the result.
- A color asset without a matched depth map uses honest color-only staging. It does not claim free-view 3D geometry.

## Environment

```powershell
Copy-Item .env.example .env.local
# Set MINIMAX_API_KEY in .env.local
npm.cmd run dev -- --host 127.0.0.1 --port 8143
```

Canonical workbench: `http://127.0.0.1:8143/workbench.html`

Generated bytes and metadata live under `.signal-lab-cache/assets/` by default and are ignored by Git. `SIGNAL_ASSET_CACHE_DIR` may point to another local cache root.

# R39 · 效果优先工作台交付契约

## 宏观目标

用户只需要描述期望的对象、受众、氛围与变化，系统负责选择素材、生成专属 Three.js 网页、运行浏览器验收，并只交付一个当前最佳结果。工作台不是模板选择器，也不是模型与工程能力的陈列页。

## 本轮范围

- Entry mode: revision-led
- Target user: 希望把一个想法直接变成可运行网页的创作者
- First impression: 一个清楚的主操作，且能看懂系统正在如何保证最终效果
- Visual ambition: 工作台保持克制、编辑化；最终作品允许沉浸式、电影化和不同创意方向
- Architecture: 左侧目标描述与单一主操作，右侧持续显示真实结果
- Evidence branch: R38 云上观测站连续空间叙事与现有工作台自动 Codex 构建链路
- Environment constraints: 复用本地 Codex、项目素材目录与 MiniMax 图片适配器；不增加新供应商、账号或后端系统

## 唯一主流程

1. 用户描述目标并点击“生成并构建最佳网页”。
2. 模型解释目标并形成可执行页面方向。
3. 素材按最终效果选择：项目优选或用户素材优先，MiniMax 只作适配场景的备用，无需素材时使用程序化 Three.js。
4. Codex 生成该目标专属的页面代码并通过编译与安全门禁。
5. 浏览器采集首屏、中段、末段与移动端，保留原版或独立精修版中更好的一个。
6. 工作台只把最终最佳网页作为主结果；候选、Manifest 和内部报告留在折叠区。

## 必须保留

- provider 与画质偏好
- 任务持久化和刷新恢复
- 项目优选素材、用户素材导入和 MiniMax 备用能力
- Codex 专属生成、非破坏式精修与失败回退
- 已筛选的研究样例和工程产物检查入口

## 不做

- 不把 MiniMax 使用次数当成成功指标
- 不用基础几何或低质量占位图冒充关键主体
- 不让用户手动完成“生成候选 → 生成素材 → Codex 构建 → 视觉精修”四次点击
- 不在本阶段继续增加供应商、3D 模型生成、视频导出或案例数量

## 可观察完成标准

- 页面只有一个主要生成操作，按钮文案与真实行为一致
- 主按钮附近持续显示“素材 → Codex 构建 → 浏览器验收”三段交付路线
- 观测站 brief 能匹配三张项目优选连续素材并明确跳过 MiniMax
- MiniMax 路线明确标记为备用，阻断路线不产生伪结果
- 生成、构建、验收与最终完成状态来自真实阶段事件，不用假进度冒充完成
- 桌面与 390px 移动端可读、可操作，无横向溢出
- 单元测试、浏览器检查和生产构建通过

## 实现结果

- 工作台只保留一个主按钮“生成并构建最佳网页”；本地草案不会再误触发 Codex 自动构建，远程模型结果仍会自动接续完整链路。
- 新增持久可见的三段交付路线：素材智能选择、Codex 专属构建、真实页面验收。
- 路线状态由实际生成事件驱动，不再把模型方向生成完成误报为整个网页交付完成。
- 素材回执带有明确 `catalog / generate / procedural / blocked` 路由；项目优选素材返回真实素材数量，而不是去重后的 modality 数量。
- 观测站目标匹配三张连续素材，并把三张素材 URI 全部送入专属构建请求；MiniMax 没有被调用。
- 最终完成状态会移除构建占位层，露出真实 iframe 页面；失败或素材阻断时保留原结果。
- 左侧大标题缩小，交付路线移到右侧结果区顶部，避免被左侧内部滚动截断；390px 下按目标、按钮、路线、结果自然排列。

- R39 定向用例：`e2e/outcome-first-workbench-r39.spec.ts`；验证 3 个观测站项目素材进入 Codex 构建请求、最终 iframe 可见、桌面与 390px 无横向溢出、控制台无错误。
- 浏览器用例使用本地模拟 Codex 回执，避免为了重复证明流程再次消耗模型；真实模型、真实三素材和最终观测站结果由 R38 的 `dedicated-896cfb7e6657` 与四状态证据承接。

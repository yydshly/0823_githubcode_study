## Purpose

Generated runs are working material, not a product catalog. The project keeps one runnable representative per research goal. Other iterations are removed after their reusable conclusions are recorded here.

## Selection policy

1. Final browser quality outranks recency, model cost, or novelty of technique.
2. One goal keeps one runnable case.
3. A failed or redundant run contributes a written conclusion, not another card.
4. New generated pages are not automatically archived. Promotion to a research case is an explicit maintainer decision after browser review.
5. Cases are evidence and regression fixtures; they are never templates for a new user brief.

## Product consequence

The user-facing creation loop is now:

```text
describe the intended webpage
-> generate one dedicated result
-> revise that result in natural language
-> optionally run visual review
```

Research-case promotion is outside that primary loop. The current next product milestone is improving generation and revision quality, especially automatic cross-state layout checks before a child version is accepted.

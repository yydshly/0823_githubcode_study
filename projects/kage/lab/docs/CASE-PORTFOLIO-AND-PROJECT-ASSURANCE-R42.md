# R42：精选样例与项目保障

## 项目目标

用户只描述想法、对象、受众、情绪和希望发生的变化，系统负责选择表现手段、生成或调用素材，并构建一个可直接体验的 Three.js 网页。

阶段目标不是继续堆叠功能，而是证明一条稳定闭环：

`想法 -> 表达方案 -> 素材 -> 网页构建 -> 浏览器验收 -> 最多一次精修 -> 最终页面`

Codex 是当前主构建模型。MiniMax 只作为可替换的素材来源；只有在结果更好时才使用，不为了“已接入”而强制调用。

## 精选样例策略

案例库只保存少量、互相补充、经过优化的最终结果。生成目录可以保留调试记录，但不等于案例库。

| 方向 | 推荐保留结果 | 证明的能力 | 状态 |
| --- | --- | --- | --- |
| 时装材质叙事 | `dedicated-ba4e9d10caaa-depth-field` | 生成素材、透明层次、全屏融合、编辑感排版 | 精选候选；只保留深度场最终版 |
| 生物材料展陈 | `dedicated-r36-delivery-final` | 主体素材融入、材质感、叙事滚动 | 备用正式样例 |
| 智能声音产品 | `dedicated-1edb98865f4c` | 产品发布页、程序化场景、完整行动收束 | 备用正式样例 |
| 梦境记录产品 | `dedicated-8574ee46ab16` | 真实空间、连续状态、记忆碎片到 CTA 的叙事 | 当前新增正式样例 |

以下内容不进入精选库：

- 同一 brief 的早期版本、失败版本和视觉修复中间版本；
- 仅能证明页面可运行、但视觉效果未达到标准的默认生成；
- 素材存在但没有在最终画面中清晰发挥作用的结果；
- 依赖说明文字才能理解效果的技术演示。

案例状态分为两层：

- `refined`：人工确认可作为备用样例，保留完整 bundle 和生成记录；
- `featured`：通过固定视口、关键进度、素材可见性和视觉验收后，才出现在首要推荐位置。

每个 brief 在案例库中只保留一个当前最佳结果。新结果胜出时替换旧条目，而不是新增一条近似案例。

## 最小生产架构

不拆成复杂微服务，只保留五个明确职责：

1. **Coordinator**：接收 brief，记录任务状态和耗时，决定 Codex 与可选素材提供方。
2. **Creative plan**：把自然语言转成叙事、镜头、交互、素材和视觉连续性约束。
3. **Asset pipeline**：生成、验证、缓存素材；记录来源、尺寸、用途和可见性要求。
4. **Page builder**：Codex 基于稳定 SDK 构建专属页面，而不是套换肤模板。
5. **Verifier and curator**：在真实浏览器中检查关键状态，通过后归档唯一最佳案例。

任务状态固定为：

`queued -> planning -> assets -> building -> verifying -> refining_once -> ready | failed`

只允许一次自动精修。第二次仍未通过就返回明确失败原因和当前最好结果，避免无限生成。

## 质量门槛

### 1. 素材门槛

- 所有必需素材返回成功，并在最终页面中实际可见；
- 同一主体的开场、中段和结尾保持身份、色彩与形态连续；
- 透明素材无棋盘格、硬矩形边界或明显贴图框；
- 首屏关键素材总量建议不超过 6 MB，单张图建议不超过 3 MB；
- 素材生成失败时允许使用程序化 Three.js 表达，但必须在结果记录中说明。

### 2. 构建门槛

- 编译通过；无阻塞控制台错误；无横向溢出；
- 页面必须包含真实 Three.js/WebGL 表达，不能只是静态大图加文字；
- 页面结构、清理逻辑和事件生命周期符合项目 SDK；
- 生成代码只能写入独立 run 目录，不能修改生成器自身。

### 3. 体验门槛

- 在滚动进度 `0 / 0.5 / 1` 三个状态分别留下确定性证据；
- 鼠标与滚动使用平滑目标值，不直接抖动相机或物体；
- 首屏 3 秒内能看懂主体和情绪；中段有明显变化；结尾 CTA 可读可操作；
- 移动端、桌面端以及 `prefers-reduced-motion` 都有可用结果；
- 无意外大字号遮挡、素材硬边、首屏空白或主体与背景割裂。

### 4. 案例入库门槛

- brief、模型、素材来源、代码 bundle、构建报告和验证报告完整；
- 精选案例必须对应最终生成效果，不能用占位截图或早期版本代表；
- 同一目标只展示一个最佳版本；失败记录只在内部保留七天用于诊断；
- 浏览器截图失败和页面运行失败分开记录，不能因为截图工具超时误判页面失败。

## 当前阶段验收线

用五个差异足够大的 brief 做回归：产品、时装、真实空间、文化展陈、抽象情绪。

达到以下条件即结束当前阶段，不再继续扩展能力：

- 五个 brief 都能从工作台生成可打开的独立页面；
- 至少四个首次生成通过机械检查；
- 最多一次精修后五个全部通过机械检查；
- 至少三个达到人工视觉“可展示”；
- 单次端到端目标时间不超过 12 分钟，超时必须显示具体卡在哪一阶段；
- 案例库最终只保留 4–6 个互补的精选结果。

在此之前暂不增加 GLB 自动建模、音频响应、MP4 导出、更多模型供应商或多人协作。它们不是当前闭环成立的必要条件。

## 接下来三项实施

1. **案例收口**：把上面的最终结果归入精选/备用分类，隐藏同 brief 的较差历史条目；案例卡片展示“证明的能力”和验收状态。
2. **任务可靠性**：生成任务持久化、分阶段超时、失败原因、重试上限和耗时统计；页面关闭后任务仍可恢复。
3. **固定基准回归**：把五类 brief 与关键滚动状态做成一条自动验收命令，任何生成器或 SDK 修改后都运行。

完成这三项后，再决定是否进入下一阶段；不以继续增加 demo 数量作为进度。

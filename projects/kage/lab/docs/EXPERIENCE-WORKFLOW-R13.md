# R13 体验与创作工作流契约

## 目标

用户只需要描述一个期望的想法，系统把它构建成具有明确视觉主角、空间关系、镜头节奏和交互反馈的 Three.js 网页。素材、实现路线和技术复杂度服务于最终效果，不把固定 Demo 或工程面板当作产品本身。

## 双界面职责

- **目标网页**：沉浸式成品。进入时建立情绪，章节内发生内容相关的视觉变化，变化完成后留出稳定阅读时间，再平滑转场。
- **创作工作台**：混合式创作者界面。默认流程为“描述 → 生成 → 选择 → 调整 → 打开/交付”；模型依据、能力缺口、运行证据和 Manifest 放入高级验证层。

## 运动与交互规则

- 滚动驱动叙事时间线，不直接追逐滚轮增量。
- 每章包含建立、展开、停留、转场四个阶段；镜头与场景状态使用同一缓动节奏。
- 指针只提供细微空间反馈，松开或离开后平滑回中；触屏不依赖悬停。
- 减弱动效时冻结在可读、完整、具有代表性的构图。
- 页面加载和 WebGL 降级不能阻断正文、导航和最终行动。

## 视觉优先级

1. 模型生成或项目资产承担视觉辨识度。
2. Three.js 承担空间、深度、镜头、响应和合成。
3. DOM 承担可读叙事、导航和行动。
4. 粒子、辉光和色差只能强化主角，不单独充当创意。

## 工作流能力边界

- 本地解释器可以离线生成可运行方向。
- 本地局部调整只支持已实现的标题、强调色和更慢节奏，不猜测未支持指令。
- Codex / MiniMax 可用时再扩展解释与素材生成；无 API 时仍保留完整本地闭环。
- “打开/交付”只指向真实可运行网页；未实现打包下载前不伪装成导出。

## R13 实现与证据

- `ExperienceSegment.phase` 明确建立、展开、停留和转场阶段；滚动时间线为阅读留出稳定窗口。
- 旗舰体验每章包含入场、完整和收束三个场景关键帧，深度、共振、粒子和雾随语义焦点变化。
- 工作台暴露五步创作状态；自然语言调整与打开完整网页是主操作，质量门和工程产物默认折叠。
- 减弱动效嵌入预览收到父页面进度后会显式请求稳定帧。
- 单元测试：19 个文件、51 项全部通过。
- Chrome 端到端测试：39 项全部通过，覆盖桌面、390px 手机、减弱动效和语义回退。
- 生产构建通过；主体验包仍有约 650 kB 的既有拆包告警，未在本轮伪装为已优化。

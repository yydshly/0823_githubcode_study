# 综合能力场景分析

## 场景目标

把 Claude of Tanks 的程序化载具、地图、车辆运动、武器、弹道、命中、战损、环境特效、相机时间线与浏览器捕获能力放进同一个 20 秒 Scene Studio 场景，验证这些能力是否能够通过公开 `window.__STUDIO` 契约组合，而不是只存在于彼此隔离的截图或测试中。

本场景不是 122 辆载具、20 张地图和全部参数排列的穷举。它是一个“能力类型全集”组合场景：以 4 辆代表性载具和一张沙漠地图覆盖 Studio 当前暴露的全部 17 类效果。

## 运行入口

```powershell
powershell -File projects/claude-of-tanks/scripts/start-demo.ps1
```

打开：

<http://127.0.0.1:4173/studio?map=desert&showcase=capabilities&nogate=1>

左下角研究导演面板提供播放、暂停、重置、五段跳转、2560px 截图和 20 秒 WebM 录制。注入由外层 Vite 配置完成，上游 submodule 不需要修改。

## 叙事结构

| 时间 | 场景段落 | 组合能力 |
| --- | --- | --- |
| 0–2.8s | 战场与程序化载具 | Sirocco Wadi 地形、道路、植被、结构、光照；T-90M、M1A2、M2A2 Bradley、Tiger I 残骸 |
| 2.8–7.2s | 运动与武器表现 | 三条车辆轨道、地形贴合、履带滚动、扬尘、排烟、机枪弹链、主炮炮口焰、后坐和曳光弹 |
| 7.2–11.8s | 命中语言 | 穿透、未穿透、ERA、间隙装甲吸收、跳弹火花、HE 命中、装甲伤痕 |
| 11.8–16s | 战场破坏 | 小/中型爆炸、炮击环、断履带、发动机烟、持续燃烧、冻结开火与冻结爆炸构图 |
| 16–20s | 击毁与英雄镜头 | 大型弹药架爆炸、炮塔抛离、残骸状态、火焰与烟柱、战后编队构图 |

## 覆盖的全部 Studio 效果类型

`fire`、`muzzle_flash`、`tracer`、`impact`、`sparks`、`explosion`、`tank_kill`、`dust`、`engine_smoke`、`burning`、`detrack`、`firing_moment`、`explosion_moment`、`mg_burst`、`barrage`、`armor_scar`、`exhaust`。

场景共编排 25 个效果实例，因为 `impact` 和 `explosion` 需要多个实例才能表达不同命中语言和尺寸层级。

## 能力分析

| 能力层 | 场景中的证据 | 能说明什么 | 不能说明什么 |
| --- | --- | --- | --- |
| 程序化载具 | 四辆不同年代/类别车辆由真实 spec ID 构建 | 车辆工厂可以跨 MBT、IFV 和历史车辆复用 | 没有证明全部 122 辆同时加载的性能 |
| 地图系统 | 沙漠高度场、道路、建筑、植被、地表材质和阴影共同运行 | 地图不是背景图片，而是运行时世界 | 单场景没有穷举 20 张战斗地图；Studio 只公开四个导演地图族 |
| 运动系统 | 三条 actor track 沿高度场推进并更新履带表现 | 时间线能复用真实车辆姿态和地形贴合 | Studio 轨道是编排运动，不是玩家驾驶物理或 AI 决策 |
| 武器表现 | 机枪弹链、炮口焰、后坐、实体验证弹和冻结开火构图 | 同一 FX 语言同时支持实时事件和宣传静帧 | Studio `fire` 弹只与地形碰撞，不会自动对演员计算穿深伤害 |
| 命中/装甲语言 | 多种 impact kind、跳弹火花、ERA、间隙吸收和永久伤痕 | 视觉层能表达战斗模拟产生的不同结果 | 这些 Studio 事件是导演指定结果，不是本场景实时求解的装甲判定 |
| 战损状态 | 断履带、发动机烟、燃烧、残骸、炮塔抛离 | 车辆表现支持可组合、可回放的状态层 | 不等于模块维修、乘员或火灾模拟正在 Studio 中运行 |
| 环境 VFX | 扬尘、排烟、炮击、三档爆炸、火球和烟柱 | 粒子池与确定性事件能构成连续战场叙事 | 画面质量和性能仍依赖 GPU、DPR 和同时存活的粒子数量 |
| 导演与相机 | 6 个镜头、cut/linear 转场、五段跳转 | 项目具备可编排的 Web 3D 宣传片基础 | 相机轨道保存绝对世界高度；跨地图必须重新用高度场换算 |
| 输出 | 2560px PNG、浏览器 WebM 入口 | 场景可直接转成研究截图或宣传素材 | WebM 当前不混入游戏音频，发布 MP4 仍需转码和音频后期 |
| 确定性 | 固定 seed、固定 60Hz 效果回放、可 seek | 同一场景 JSON 可被审查、重放和自动测试 | 浏览器视频编码字节不会跨机器完全一致 |

## 运行验证

验证脚本：[`../scripts/verify-capability-showcase.mjs`](../scripts/verify-capability-showcase.mjs)

最终结果：

- `PASS`：地图为 `desert`；
- 4 个演员全部构建；
- 25 个效果实例全部进入效果栈；
- 17 个 Studio 效果类型无遗漏；

- 浏览器控制台错误为 0；

## 视觉审查与修正

第一版结构测试通过，但镜头使用绝对 Y 值，进入沙漠地形或被建筑遮挡，因此没有被当作完成。最终版本先把每个镜头的 `pos` 和 `lookAt` 作为相对地表高度交给真实高度场换算，再写回 storyboard 的绝对世界坐标。

最终画面满足：开场建立地图尺度；中景保留车辆与道路关系；结尾明确呈现击毁车辆、烟柱和推进编队。导演面板使用 DOM 提供说明和控制，WebGL 负责空间、车辆、运动和战损记忆点。

## 有界结论

这个组合场景证明 Claude of Tanks 不只是“用 Three.js 画坦克”：它已经具备把领域规格、程序化几何、运行时状态、事件化特效、地形、相机、时间线和浏览器输出组织成可重复内容生产流程的能力。

最适合复用的方向是军事/工业设备演示、机械教学模拟、车辆数字样机、交互式产品检视和自动化 3D 宣传素材。若扩展到通用 3D 产品，应保留渲染、事件、时间线、Gallery/Studio 和验证管线，替换坦克规格、弹道、装甲与战损领域模块。

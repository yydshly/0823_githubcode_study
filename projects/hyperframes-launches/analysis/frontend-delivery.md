# HyperFrames 演示页交付契约与覆盖清单

## 设计契约

- 输入类型：基于用户目标与上游仓库证据的 brief-led 实现。
- 目标用户：第一次接触 HyperFrames 的产品负责人、内容自动化开发者与技术决策者。
- 首屏目标：在一个屏幕内理解“它是用 HTML/CSS/JavaScript 制作可编程视频，并可检查、预览、渲染”的核心能力。
- 视觉方向：沿用本站深色编辑型信息架构；强调证据、案例与可复制命令，不引入与内容无关的装饰。
- 信息架构：结论 → 原理 → 全量案例 → 实测证据 → 使用方法 → AI 新闻视频扩展。
- 核心旅程：首页进入项目页 → 理解能力与原理 → 浏览 19 个案例 → 复制本地命令 → 选择扩展路径。
- 支持范围：桌面与移动端响应式布局、键盘可访问链接、系统减少动画偏好；本站当前仅支持深色主题。
- 状态模型：静态研究与演示页面，不依赖登录、接口请求、加载态或错误态；上游播放器和渲染由独立命令启动。
- 真实性边界：源码库存、CLI lint、运行时 check、实际 render 与公开成片分别标注；不把“仓库中存在”误写为“最新版 CLI 全部兼容”。

## 2026-08-23 视频优先修订契约

- 修订类型：revision-led；用户明确指出现有网页需要点击外部链接，不能构成“直接演示”。
- 当前浏览器证据：1440×1000 首屏中 `video=0`、`iframe=0`，19 个案例均为外部链接；首屏焦点仍是解释性文字。
- 选定模式：产品案例展厅；证据链为本地模板源码 → 本地实际渲染 MP4 → 页面内原生视频播放 → 浏览器运行证据。
- 新的第一印象：打开页面即看到真实成片在播放，不需要先理解概念或点击外站。
- 新的核心旅程：进入页面 → 首屏观看主演示 → 向下直接播放不同能力案例 → 再阅读原理、命令和扩展说明。
- 视频行为：首支视频 `autoplay + muted + loop + playsinline + controls`；其余视频页面内可播放，使用 `preload=metadata` 控制初始负载。
- 降级边界：浏览器禁止自动播放时仍显示原生播放控件与封面首帧；减少动画偏好下停止自动播放但保留手动播放能力。
- 发布边界：只使用本地实际渲染的代表性成片，不把外部播放器链接伪装成站内演示；素材商业许可约束保持不变。

## 2026-08-24 全量样例墙修订契约

- 修订类型：revision-led；用户要求“样例也直接展示在网页”，即完整案例不能继续只是折叠外链索引。
- 当前浏览器基线：页面有 7 个 `video`、6 个直接演示卡片、19 个外部案例链接，但 19 个案例卡片内部 `video=0`。
- 选定模式：全量产品案例墙；证据链为上游公开 viewer / 本地模板 → 可播放媒体或本地渲染 → 页面内播放器 → 浏览器逐项验证。
- 核心旅程：打开页面观看主演示 → 浏览 19 个顶层案例且无需离站 → 按需手动播放或进入视口预览 → 再查看源码。
- 视觉层级：保留首屏主演示；代表短片区之后直接出现 19 项样例墙；源码链接作为每张视频卡片的次要操作。
- 性能边界：19 项不得同时自动播放；首屏之外使用 `preload=none/metadata`、IntersectionObserver 与单卡播放约束。
- 媒体边界：优先使用可验证的公开成片媒体；没有公开成片时使用本地实际渲染，不用静态文字卡冒充演示。
- 发布边界：远程媒体保留来源标记；本地复制或渲染的视频保留许可提醒，不扩大商业使用授权。

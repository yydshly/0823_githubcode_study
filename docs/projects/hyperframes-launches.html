00 / 最终结论

它不是特效库，而是一台网页离线渲染器。

这次研究后，我们把案例、引擎和 HeyGen 平台能力分开理解。看完下面四点，就能判断它是否适合自己的项目。

案例库

你现在看到的仓库

hyperframes-launches 是 19 组 HeyGen 发布视频工程案例，不是 HyperFrames 引擎源码。

核心原理

网页按时间逐帧渲染

无头 Chrome 定位到每一帧对应的时间，离线渲染网页画面，再由 FFmpeg 编码和混合音频。

能力边界

不生成特效或数字人

动效来自 HTML/CSS/GSAP/Three.js；数字人、口型与声音属于 HeyGen 平台或其他上游生成服务。

技术选择

Remotion 可以替代

React 视频系统优先 Remotion；需要直接复用 HTML、GSAP、WebGL 或让 Agent 写普通网页视频时再考虑 HyperFrames。

我们的决定：保留它作为发布片、HTML 原生视频和 Agent 工作流研究参考，不把它设为核心生产依赖。一次性网页演示用录屏；需要稳定重渲染、批量变量、多语言和多画幅时，才使用 HyperFrames 或 Remotion。

02 / 原理

本质是离线逐帧渲染，不是实时录屏。

它让浏览器跳到第 0 帧、第 1 帧、第 2 帧对应的精确时间，分别渲染画面，再编码成 MP4；机器渲染快慢不会改变最终视频的帧率和节奏。

01内容与素材

脚本、数据、Logo、图片、B-roll、旁白

02HTML 场景

DOM、CSS、SVG、Canvas、子合成

03时间定位

start、duration、track 与 seekable 动画

04逐帧捕获

Headless Chrome 渲染每个明确时刻

05成片

FFmpeg 编码、混音，输出 MP4

04 / 复杂目标实战

REAL BUILD · ONE TEMPLATE → MANY VIDEOS

建设一个 AI 内容视频工厂。

目标不是“做一支漂亮视频”，而是把每天变化的数据稳定变成可发布成片：结构只建设一次，标题、数字、洞察、来源、渠道和品牌主题按每条任务自动替换。

它在链路中的位置

位于内容系统的“成片末端”

上游负责采集、事实校验和写稿；HyperFrames 负责把已确认信息变成确定性画面并渲染。

不适合替代什么

不是自由生成式电影模型

它不替代实拍、写实人物生成或开放式镜头创作；它擅长可控、可复用、可审计的视频工程。

02

如何新增第三支

复制 batch.json 中一行，修改标题、数字、洞察、来源、渠道与主题色，再运行同一命令。无需复制或编辑时间轴。

npx hyperframes render \
  --batch batch.json \
  --output "renders/{name}.mp4" \
  --strict-variables .

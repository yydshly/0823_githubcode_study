01 / 学习定位

仓库是书的练习场，理解才是最终产物。

阅读告诉你概念是什么，Notebook让概念发生在眼前。我们的任务不是跑完所有单元格，而是把每一章变成一个能够回答、验证和迁移的问题。

01读问题

先明确本章试图解释什么，不从术语表开始。

02做预测

运行前先写下你认为会发生什么，以及理由。

03改实验

不止复现原代码，改变输入或参数观察差异。

04讲明白

不用书中原句解释现象，再迁移到新任务。

02 / 知识地图

12章不是12份代码，而是6组需要想明白的问题。

先用问题定位学习目标，再看概念和代码。每张卡片最后的“理解标志”，比“Notebook已经运行”更重要。

03 / 理解方法

理解不是“看懂了”，而是完成一轮主动循环。

每章都重复同一套动作。运行代码只是中间一步；真正的结束条件，是你能解释观察结果，并预测修改之后会发生什么。

  1. 01提问题本章到底解释什么？
  2. 02先预测运行前写下预期
  3. 03跑原例复现书中的现象
  4. 04改变量只改变一项条件
  5. 05看差异记录结果如何变化
  6. 06做解释用自己的话说原因
  7. 07再迁移换一个新问题验证
以Tokenizer为例

不要只记住“Tokenizer把文本切成Token”。

  1. 先问模型看见的是字、词，还是其他东西？
  2. 再做把同一句中英混合文本交给5个Tokenizer。
  3. 再改替换大小写、数字、中文和emoji，比较Token数量。
  4. 最后解释切分差异为什么会影响信息保留、上下文和成本？

练习 01 · CHAPTER 02直接运行

同一句话，模型为什么会“看到”不同长度？

先预测 中文、emoji、大小写和数字，会被不同模型切成相同数量的Token吗？

12.0*50=600
→
改变条件

同一段文字分别交给5个Tokenizer，转换成模型真正接收的Token ID。

→
观察差异
BERT uncased23emoji/中文丢失

05 / 学会标准

运行完成不等于理解完成。

一个概念至少要通过三层检查。它们不是自动打勾的进度，而是你学习后需要亲自回答的问题。

LEVEL 01

说得清

合上书，不照抄术语，用自己的话解释机制、输入、输出和观察到的现象。

检查：为什么会这样，而不只是“结果是多少”？
LEVEL 02

改得动

改变一个输入、参数或模型之前，先预测结果，再用实验检查自己的预测。

检查：变化是否符合解释？不符合时哪里理解错了？
LEVEL 03

用得上

面对一个新任务，能够选择相关概念、设计最小实验，并判断失败发生在哪一环。

检查：换一个数据集或场景，方法是否仍然成立？

06 / 材料边界

实验记录能支持理解，但不能替你理解。

书籍负责
提供概念顺序、解释、图示和经过设计的Notebook示例。
我们负责
提出中文学习问题、复现实验、改变条件、记录现象并形成自己的解释。
证据负责
固定源码与运行结果，保证页面中的现象可以回查，不把推测当成事实。
当前边界
首轮实践只覆盖第1—3章的四个基础问题，其余章节仍是后续学习内容。

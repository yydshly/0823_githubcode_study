02 / CONTROL PLANE

“调度”不是 AI 猜测，而是一段可测试的选择过程。

路由器负责决定先加载哪个专业 Skill；安全契约决定能否行动；工具层决定现实中可以调用什么。三者不能混为一谈。

ROUTER / 选择谁

正则命中、累计计分、优先级破同分

  1. must 命中，规则进入候选。
  2. mustAll 补充必要上下文。
  3. exclude 排除“越狱”等歧义。
  4. 同一路由多条规则命中则加分。
  5. 最高分为 PRIMARY；同分看优先级。
  6. 完全未命中时回退 R0 通用逆向。
SCOPE / 能不能做

授权、资产、活动、网络四个硬条件

授权

04 / KNOWLEDGE MAP

安全是目标空间，逆向是其中一种理解手段。

逆向回答“程序如何工作”；安全回答“资产面临什么风险、如何验证、检测和修复”。二者经常交叉，但不是包含方向相反的同义词。

CYBERSECURITY / 更大的问题空间 保护资产、身份、数据和业务连续性
进攻验证防御检测事件响应平台治理
REVERSE ENGINEERING / 一种技术方法 在缺少源码或文档时理解实现

逆向但不一定是安全：兼容旧格式、迁移数据、理解遗留软件。

安全但不一定需要逆向：云权限审计、API 越权检查、日志取证。

交集：恶意软件、漏洞研究、客户端安全、固件与协议分析。

MAP A

逆向：从未知对象到可解释模型

  1. 01
    Triage · 识别

    确认文件格式、平台、CPU 架构、语言、打包器、保护机制和可用符号。输出“下一步值得走哪条路径”。

    魔数 · PE/ELF/Mach-O · APK/DEX · imports · strings · entropy
  2. 02
    Static · 静态理解

    不运行目标，观察反编译代码、汇编、资源、交叉引用、控制流和数据流，建立函数与模块假设。

    decompile · disassemble · CFG · xref · symbol recovery
  3. 03
    Dynamic · 运行验证

    在隔离环境中调试、Hook、采样网络与内存，验证静态假设并捕获真实参数和状态变化。

    debugger · breakpoint · Frida · tracing · memory · traffic
  4. 04
    Deobfuscate · 消除阻碍

    处理混淆、加壳、虚拟机、反调试和环境检测；目标是恢复可分析结构，而不是盲目“破解”。

    unpack · OLLVM · control-flow flattening · anti-debug · VM opcode
  5. 05
    Synthesis · 建模与复现

    把观察整理成调用链、算法、协议状态机或可运行的最小复现，并注明证据和不确定性。

    call flow · data model · protocol grammar · reproduction · confidence
反编译

把字节码或机器码转换为接近高级语言的表示；可读性不等于原始源码。

反汇编

把机器码转换成汇编指令；更接近真实执行，但需要理解架构与调用约定。

Hook

在运行时拦截函数调用，观察或有限修改参数、返回值和行为。

符号恢复

通过元数据、模式和旧版本信息，为匿名函数重新建立名称和职责。

协议恢复

从流量与程序逻辑推断字段、编码、状态和错误处理。

去混淆

把刻意隐藏控制流、字符串或运行语义的结构恢复为可分析形式。

MAP B

安全：从资产与信任边界到持续改进

01定义范围

明确资产、所有者、授权、数据敏感度、允许活动和不可接受影响。

scope · asset · threat model
02发现暴露面

枚举接口、端口、身份、依赖、客户端、云资源和信任边界。

recon · inventory · SBOM
03验证弱点

用最小影响方式证明错误配置、漏洞或设计缺陷是否真实可利用。

authn · authz · injection · exploitability
04评估影响

把单点问题放进攻击路径，判断对机密性、完整性、可用性和业务的影响。

finding · path · severity
05检测与响应

建立日志、规则和取证路径，确认组织能否发现、遏制并解释攻击。

SIEM · Sigma · YARA · timeline
06修复与复测

调整代码、配置和架构后复现原始路径，确认问题关闭且没有引入旁路。

remediation · regression · assurance

身份认证 AuthN

你是谁？密码、证书、令牌和设备信任是否可靠。

授权 AuthZ

你能做什么？对象级、功能级和租户边界是否正确。

攻击面

外部可以触达的入口、数据、组件和关系集合。

信任边界

数据或身份跨越不同可信级别的位置，通常是设计审查重点。

可利用性

弱点是否能在现实约束下形成稳定影响，而不只是理论可能。

可检测性

攻击发生时，日志、告警和调查证据是否足够及时且可信。

05 / VALUE & BOUNDARIES

当前最值得学的是架构，不是一次装完所有工具。

对于暂时不做安全实操的人，这个仓库首先是一份“大型专业 Skill 系统如何工程化”的案例。

现在学习

路由单一事实源

把任务与 Skill 的映射集中管理，给歧义、回退和优先级建立可测试规则。

现在学习

按需加载

只给 Agent 一个 PRIMARY 和必要协同，减少上下文堆叠与职责冲突。

现在学习

能力索引

区分“文档说能做”和“当前机器真的有工具可做”。

现在学习

证据化完成

把观察、结论与路径绑定，避免用流畅文字替代真实验证。

以后再做

安全工具链安装

只有产生真实逆向或授权安全任务时，再在隔离环境中按需准备。

保持警惕

强制提示与自动执行

仓库中的“立即执行、自动安装”不能高于宿主安全规则、用户授权和人工审批。

采用建议把它当架构样本，而不是可信执行根。
  • 先读路由、Skill 契约、工具 manifest 和脚本，再决定是否执行。
  • 真实安全操作只在自有、CTF、实验室或书面授权范围内进行。
  • 安装 MCP 与第三方工具会扩大本机攻击面，优先使用隔离 VM。
  • 路由基准只能证明“选到了预期 Skill”，不能证明安全结论正确。
  • field journal 是外部记忆，不是模型训练；需要脱敏、审核和版本治理。
